# v0.46.0-nkmk.47

- **Upstream base:** unchanged — the `v0.46.0` release tag (`aedee21cb`)
- **Range:** `v0.46.0-nkmk.46..v0.46.0-nkmk.47`
- **Released:** 2026-11-25

This release keeps a coding agent from taking the person's keystrokes. When an agent moves the person's focus, the move waits for a pause in their typing, and a short guard catches what they type next. The MCP tools also get easier for agents to call.

## Added

- **Friendly focus.** An agent's `focus-pane-id`, `go-to-tab*`, `go-to-next-tab`, `go-to-previous-tab`, `move-focus*` and `focus-next-pane`/`focus-previous-pane` wait until the person's input has been idle for `focus_wait_idle` (default `"2s"`), and apply anyway after `focus_wait_max` (default `"5m"`). A new pane, tab, run or plugin made with focus, and `go-to-tab-name --create`, is made and runs at once; only the move to it waits. A held call returns at once with `focus: pending`; one that moved ends with `focus: applied` (`"focus"` in `--json`). Either key at `0` applies at once. Capability: `focus-wait`.
- **`zellij action --now <verb>`** applies an agent's focus move at once. `zellij run --focus --now` and `zellij plugin --focus --now` do the same.
- **Virtual focus.** While a focus change an agent asked for waits, that agent's `--focused` writes go to the pane it asked for, never to the person's pane. The agent is keyed by its `ZELLIJ_PANE_ID`.
- **The input guard.** When an agent's call moves a client's pane, tab or input mode, that client's input is held for `input_guard_ms` (default 500; `0` turns it off):
  - plain typing goes to the pane the person was in (`input_guard_typing "drop"` drops it instead);
  - chords and clicks are dropped; the wheel passes;
  - typing that keeps coming holds the guard until a pause, 3 s at most;
  - the pane frame says `input held`.

  The guard always ends on the clock, and on a detach, a tab drain or a move that is not the agent's. Capability: `input-guard`.
- **MCP:**
  - `zellij_write_input then: quiet | agent_idle | match` waits after the input and returns the pane's screen in the same call.
  - `keys` takes a list of keys, such as `["Down", "Enter"]`.
  - A remote host can be written as the start or the end of its name.
  - A `zellij_wait_for` timeout is an outcome, `timed_out: true`, not an error.
  - A call now names the parameters it ignored (`ignored: [...]`). A `name` on a non-tab pane is ignored and points at the handle.
  - `zellij_close` reads what to close from its target; `operation` is optional.
- **Attention dwell.** `bell_clear_delay_ms` now also governs the attention markers on frames, tabs and the inbox. A look counts only once it has lasted the dwell, so skipping past a pane no longer clears its `done` mark. `0` takes upstream's path.

## Fixed

- `list-agents --all-sessions` printed `[]` and exited 0 when the shell resolved the wrong socket dir (Linux with no `XDG_RUNTIME_DIR`, macOS with no per-user `TMPDIR`). It now exits 2 with one stderr line naming where it looked, when sessions answer in another candidate root or the dir's parent does not exist. A machine with no session yet still gets `[]` and 0. Every "no active session" error carries the same note.
- A later attention idle check no longer postpones an earlier one.
- `not_ready` is in the MCP output schema's reason enum, so a validating client no longer drops `zellij_create`'s answer.
- The MCP instructions no longer open with a CLI-only line.
- An agent started through a launcher wrapper that adds its own flags is recorded with the caller's arguments, so a restore through the wrapper no longer repeats them (`claude --settings X --settings X --resume <id>`). The wrapper exports `HARNESS_ORIGINAL_ARGS` (a JSON array of the caller's arguments) and `HARNESS_ORIGINAL_ARGS_PID` (its own pid) before it execs; zellij reads them from the agent process on Linux and macOS for `pane_command`, `list-agents` and the restore. A wrapper that sets neither works as before.
- The watchdog's upgrade restart no longer kills a running job in a clientless session. It waits while any pane runs a command that has not exited, a command pane or a shell with a foreground program, and says why once. An idle shell does not hold it.
- Follow-ups to the input guard and friendly focus:
  - an agent call that ran long (one that blocks until a pane exits) arms no guard;
  - a person's own key or click during the call is not held against them;
  - a focus change that applies at once drops one still held;
  - a move to a pane or tab that is not there is not held, and still exits 2.

## Upgrading

- **Behaviour change:** `bell_clear_delay_ms` defaults to 1000, not 0. Attention marks and the bell now need a one-second look before they clear. Set `bell_clear_delay_ms 0` to keep the old instant clear.
- The input guard and friendly focus are on by default for agent callers. A person's own keys, plugins and scripts with no agent variable are not affected. Set `input_guard_ms 0` and `focus_wait_idle "0"` for the old behaviour.
- The guard and the wait live in the server: a session picks them up when it restarts onto this build. An older server ignores the new `ActionCaller` field (`caller = 5` on the action message, with `agent`, `now` and `pane`) and moves focus at once. The contract version is unchanged.
- An older build refuses `action --now` as an unknown flag, and warns about the four new keys and ignores them. Seed the keys in a shared config once every machine runs this build.
