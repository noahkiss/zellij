# v0.45.1-nkmk.39

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the commit taken in nkmk.22
- **Range:** `v0.45.1-nkmk.38..rc/nkmk.39`
- **Released:** TODO: release pending

This release lets a controller follow a session without polling.
`zellij action watch --json` is a stream the server pushes as panes, tabs and agents change.
A new opt-in strict mode refuses to talk to a session that runs a different build.

## Added

### `zellij action watch --json`: the session pushes its changes

```
$ zellij action watch --json
{"event":"hello","server_version":"0.45.1-nkmk.39","session":"work","server_build":"same","seq":0,"epoch":"5be1c0a2d4f7e913","ts":1761900000000,...}
{"event":"agent","handle":"sunny-otter","pane_id":3,...,"seq":1,...}
{"event":"pane_opened","pane_id":"terminal_3","handle":"sunny-otter","tab_id":0,"seq":2,...}
{"event":"tab_opened","tab_id":0,"seq":3,...}
{"event":"synced","seq":4,...}
{"event":"pane_output","pane_id":"terminal_3","handle":"sunny-otter","last_output_at":1761900001234,"seq":5,...}
```

One long-lived command, one JSON object per line, written by the server as things change.

- Every line carries `seq`, `epoch` and `ts`. `seq` counts from 0 with no gaps. `epoch` is new each time a server starts. `ts` is milliseconds since the Unix epoch.
- It opens with a snapshot: `hello`, then one `agent`, `pane_opened` and `tab_opened` line for each that exists, then `synced`.
- `agent` carries the whole `list-agents --json` row, and `gone` drops it. A title change is not a change.
- `pane_opened`, `pane_exited` (with `exit_status`) and `pane_closed` carry ids only. `handle` is on every pane line, because pane ids are reused.
- `tab_opened`, `tab_closed` and `tab_renamed` (with `name`) carry the stable `tab_id`.
- `pane_output` says a pane produced output: at most one line per pane per second, with `last_output_at`.
- A pane privacy policy applies: a withheld pane never appears.
- It exits 0 when the reader closes the pipe. It exits 2 when the session goes away, and within five seconds against a server that predates it.

`list-agents --watch` rides the same stream for one session, so a state change arrives at once instead of within a second. `--all-sessions` and `--changes-only` stay a poll. Against an older server, the watch says so and falls back to the poll.

Contract: two messages, appended. `SubscribeToSessionEventsMsg` (client to server, tag 28) and `SessionEventMsg` (server to client, tag 20), which carries one JSON line.

### Strict mode: refuse a session on another build

```
$ ZELLIJ_STRICT_VERSION=1 zellij action list-tabs     # or: zellij --strict-version action list-tabs
```

By default, a CLI that reaches a server of a different build warns once and carries on. Every upgrade leaves the running session on the old build until it restarts, so that stays the default.

With `ZELLIJ_STRICT_VERSION=1` or `--strict-version`, a proven mismatch refuses instead. The message names both builds, and the exit code is 3. "Cannot tell" is not a mismatch, and the command runs.

- Gated: every `action` verb, `run`, `edit`, `plugin`, `pipe`, `list-agents`, an attach to an existing session, `subscribe`, `watch` and `action watch`.
- Exempt, because they are how you get out of skew: `ls`, `kill-session`, `delete-session`, `kill-all-sessions`, `delete-all-sessions` and every `session` subcommand.
- A new server drops the variable, so its panes do not inherit strict mode.
- ssh does not carry the variable. `zellij mcp` passes it to a remote host itself. A controller that runs its own `ssh host zellij ...` sets it on the remote command line.

## Changed

- `subscribe`, `watch` and `list-agents --all-sessions` now warn about a session on a different build, as `zellij action` already did.
- `list-events` stays a 256-entry ring in memory. FORK.md now points a consumer that follows the session at `action watch`.
