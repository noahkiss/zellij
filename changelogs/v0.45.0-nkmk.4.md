## Fixed

### Moving focus inside a stack no longer makes the shells reprint

A focus move in a stack collapses one member to its one-row header and expands another, and both
new row counts were pushed to the panes' ptys — two `SIGWINCH`es per keypress, and any prompt that
repaints on resize left a copy behind. Three focus round-trips left four prompts in the scrollback.

The bug is upstream's and predates 0.45 (zellij-org/zellij#4047, reported against 0.43). Full
frames were never affected, but only by accident: a collapsed member's single row is all frame, so
its content height saturates to zero and the unix resize call refuses a zero row count. Every other
style counts that row as content, and the resize goes through. What 0.45 changed is who lands
where — `pane_frames true` now resolves to the `titles` style, not `full`, so the default
configuration moved onto the unprotected path.

Now a member collapsed to its stack header keeps the pty size it had while expanded, and its
resize is skipped. Re-expanding to unchanged geometry writes the same size back — no signal, no
reprint. A stack that really did change size while the pane was collapsed is picked up when the
pane is focused again. The branch sits at the single point every layout pass goes through, so all
four frame styles and both stack renderings are covered.

Measured before → after, three focus round-trips, prompts in the pane:

| case | before | after |
|---|---|---|
| classic stack, default (`titles`) | 4 | 1 |
| classic stack, `pane_frames true` | 4 | 1 |
| classic stack, `pane_frame_style "full"` | 1 | 1 |
| classic stack, `pane_frame_style "top_only"` | 4 | 1 |
| classic stack, `pane_frames false` | 4 | 1 |
| stack list, default | 4 | 1 |

## Changed

### CI retries a failed whole-app test twice

The whole-app integration tests boot a real server and snapshot the whole screen, and on loaded CI
runners single tests fail on render races — two different ones failed on one commit the day this
shipped, both green on retry. `nextest` now retries a failed test twice: a race passes on retry
and is labeled FLAKY in the log, a real failure fails all three attempts.

## Upstream

`git fetch upstream` reports no commits past `f42ca3c79`. No plugin API change; plugins built
against nkmk.2 or nkmk.3 keep working, and the bundled plugins are unchanged from nkmk.3.
