# v0.45.0-nkmk.3

- **Upstream base:** `f42ca3c79` on upstream `main` (workspace version `0.45.0`) — unchanged since
  nkmk.1
- **Range:** `7f7cf2d42..main`
- **Released:** 2026-08-11

The gaps release. Everything here closes something that was half-landed, silently broken, or
promised by an earlier release and never quite delivered. Three long-standing complaints turned out
to have upstream 0.45 causes, and one feature the fork shipped in nkmk.2 had never worked at all.

**Read the breaking-change section if you build plugins against this fork.**

## Fixed

### The session manager's client list was always empty

`Ctrl+l` reported `Clients attached to this session: 0` on every machine, for one client and for
two, since the list shipped. The server builds that answer from a layout snapshot, and the
plugin-facing path removed the requesting plugin's own pane from the snapshot first — a rule that
belongs to the layout *dump*, where nobody wants the session manager recorded. The session manager
is a floating pane, and zellij focuses a new floating pane for every client in the tab, so that one
pane was the focused pane of *every* client. Removing it removed the whole list. `zellij action
list-clients` never excluded anything, which is why the CLI was right all along.

The list also read one pane layer per tab. Floating visibility is per tab while focus is per client,
so a client focused on a tiled pane in a tab where someone else had floating panes up had no row
anywhere. Both layers are read now.

### The session you are in is in the session list

The single-screen list dropped the current session in its render cache, so a user looking for their
own session found nothing and could not tell a wrong list from a missing session. It is now drawn
like any other row, tagged `<CURRENT>` (`<C>` in a narrow pane) where `[ATTACH]` would be.

The row is fully selectable — rename, kill and the client actions all route through the selection,
so a visible row the cursor refused to land on could not be acted on at all. Only attaching is
refused: `ENTER` says `Already attached to this session.` and stays put.

### A dropped session row says so

The empty-list notice claimed the server's scan had returned nothing. It could not know that — the
renderer was free to drop rows the scan *had* returned, and did, silently. The render cache now
counts what it turns into rows:

```
2 sessions hidden: the list drew fewer rows than the search returned.
```

The empty notice reports the counts the scan actually produced instead of asserting a cause.

### `pane_frame_style "top_only"` keeps its rule on a single-pane tab

Upstream 0.45's `titles` mode hides the title row when a tab holds one selectable non-borderless
tiled pane, and `top_only` inherited that. `top_only` promises one rule per pane, so the suppression
is now gated off for it — in `set_pane_frames` (the row the layout reserves) and in `render` (the
row it draws). This is why pane frames appeared to vanish after the 0.45 sync.

### `top_only` titles are left-aligned again

Upstream 0.45's frames-off renderer centers the pane title; 0.44 drew it on the left. `top_only`
keeps the pre-0.45 left-aligned title. `titles` mode keeps upstream's centered look.

### `TogglePaneFrames` can reach `top_only` again

The cycle is `full → titles → none → full`, with no seat for a fourth style. `Screen` now remembers
the last style that was not `none`, so `top_only` toggles to `none` and back to `top_only`. Every
other starting point keeps upstream's cycle.

### Stack focus wrap works under stack-list rendering

Upstream 0.45 added stack lists (`stacked_pane_list`, default on), which keep every stack member but
the visible one in `Tab::suppressed_panes` rather than in the grid — so the fork's wrap saw a stack
of one and did nothing. `Tab` gets its own wrap in the same third position, after the in-list step
and the ordinary grid move, so only a genuine dead end wraps.

## Added

### The about page names the binary macOS must trust

`Ctrl+o` then `a` ends with the path of the executable the server is running:

```
Server binary (macOS: grant Full Disk Access to this path):
/Users/<user>/.local/share/zellij/zellij-pinned
```

On macOS that is the exact string Full Disk Access needs, and until now the only way to learn it was
a log line you had to know to look for. The path is canonicalized server-side, because a package
manager puts a symlink on `PATH` while TCC records the target.

The hint half is added only when the **server's** host is macOS — the client can be somewhere else,
and the plugin has no way to ask. Off macOS the label is just `Server binary:`.

The line survives a short pane. Page components can now be marked essential, and the page drops the
largest non-essential component first — the nine-row "What's new" list long before a one-line
paragraph — until it fits. The path stays visible down to five interior rows.

### Client terminal sizes in the client list

A session is sized to its smallest attached client, and nothing said which client that was:

```
     Client          Focused pane   Size    Running
<↓↑> 1               terminal 14    160x40  zsh
     2 (this client) terminal 7     100x28  nvim FORK.md
```

The smallest client by area is drawn in the emphasis colour. The mark is withheld when every sized
client is the same size, and a client whose size the server never recorded never wins. The value is
`Screen`'s own `client_sizes` map — the same one `recompute_tab_size` takes the minimum of — so the
number on screen is the number that decides the grid.

### `resurrect_command_hints`

A resurrected pane holds the command it was running, and `ENTER` re-runs it. For a tool keyed by a
session id, re-running the bare command starts a *new* session and the old work becomes unreachable.
A hint rewrites what gets recorded:

```kdl
resurrect_command_hints {
    claude {
        match "claude"
        env "CLAUDE_CODE_SESSION_ID"
        rewrite "claude --resume {}"
    }
    opencode {
        match "opencode"
        env "OPENCODE_SESSION_ID"
        rewrite "opencode --session {}"
    }
}
```

`match` compares against the basename of the recorded command, exactly. `rewrite` must contain `{}`,
checked at parse time, and is split on whitespace rather than passed to a shell. The variable is read
from the pane's process and every process under it, breadth first: `/proc/<pid>/environ` on Linux,
`sysctl(KERN_PROCARGS2)` on macOS, nothing anywhere else. First match wins.

Best-effort throughout — no hint, no variable or no platform each record the command unchanged.
Config-file only, unset by default, and a config save applies to the next serialization without
restarting the session.

### `default_floating_size`

```kdl
default_floating_size {
    width "90%"
    height "85%"
}
```

A floating pane with no coordinates of its own lands at half the viewport, which truncates session
names in the session manager and paths in the plugin manager. Nothing in config.kdl reached that
geometry, and a keybinding cannot: `LaunchOrFocusPlugin` has no coordinates on the action, and a
keybind that spells out `width "90%"` passes `setup --check` cleanly and is then ignored.

Each axis is optional and independent; a value is a percent of the viewport or a fixed column/row
count. The block fills in only the axes the caller left open, so an explicit `--width 30%` still
wins. Applies on a config save, to panes opened after it. An absent block is byte-identical to
upstream.

Two floating panes stay their own size: the about page and the first-run wizard resize themselves
after opening, on a path that never passes through `add_floating_pane`.

### `<Ctrl l> - Clients` is named in the session manager

The client list had no advertisement anywhere on screen. The hint now sits on the save line, once,
at ordinary widths.

## Breaking changes

**`event.proto` gained two fields.** `message ClientInfo` now carries `optional uint32
terminal_rows = 100` and `optional uint32 terminal_cols = 101`, on fork-reserved tag numbers.

The addition is additive, so decoding is safe both ways: a plugin built against nkmk.2 keeps working
and treats the tags as unknown fields. The pair is read both-or-none, so a half-filled message reads
as no size rather than a fabricated dimension. Rebuild against this release's `zellij-tile` to read
the fields. The fork's own bundled plugins are rebuilt here.

The nkmk.1 requirement still stands: **anything not yet rebuilt since 0.44 must be rebuilt**, because
nkmk.1 renumbered the fork's plugin API tags. That is a wire-incompatible change, unlike this one.

## Notes

- Every nested KDL block in this changelog is written multi-line on purpose. KDL needs a `;` or a
  newline after every node, the last one before a closing brace included, so `{ match "x"; env "Y" }`
  does not parse.
- `pane_frame_style "top_only"` remains a fork-only *value* of an upstream key. A stock 0.45 build
  rejects the whole config with `Invalid value for pane_frame_style: 'top_only'`. The two new config
  blocks are fork-only *keys*, which a stock build ignores.
- The `KERN_PROCARGS2` reader in `resurrect_hints.rs` is compiled for darwin for the first time in
  this release's build.

## Upstream

`git fetch upstream` reports no commits past `f42ca3c79`. The base is the same tree nkmk.1 shipped
against, so this release carries no upstream changes.
