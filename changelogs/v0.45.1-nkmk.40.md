# v0.45.1-nkmk.40

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the commit taken in nkmk.22
- **Range:** `v0.45.1-nkmk.39..rc/nkmk.40`
- **Released:** 2026-10-31

This release stops a restart from cutting off an agent at work.
`zellij session restart` and `session down` now refuse while an agent in the session is working, waiting on the operator, or running background tasks.
`zellij action watch` also reports when a pane's title, directory or command changes.

## Added

### `session restart` and `session down` refuse while an agent is at work

```
$ zellij session restart work
session restart: refusing - 1 agent(s) in 'work' are working:
  tab "develop"  shining-foal  claude  working
Nothing was torn down. Wait for them to finish, or pass --force to restart anyway.
Exit status 4: a caller that started this in a pane that closes on exit must check it.
$ echo $?
4
```

A restart or a `down` kills every pane's process. A Claude session mid-turn loses its subagents, its running builds and its unsaved edits.

- **Busy:** `working`; `blocked` of any kind (a permission prompt, a question, a sign-in); a state this build does not know; or any background task still working, under any state.
- **Not busy:** `idle`, `done` and `error` with no background task working, and a pane that reports no state. The caller's own pane never counts.
- `--force` goes ahead as before. The exit code is 4.
- In a `run --floating --close-on-exit` pane, the refusal waits for Enter, so it stays on screen. `restart` also writes it to `restart.log` in the state directory, because `run` exits 0 whatever the restart did.
- A session that does not answer the question is retried once, then the teardown goes ahead with a warning. A wedged server is what a restart is for.
- `session up`, the watchdog and the launchd and systemd units are unaffected.

### Background tasks count on `list-agents`

Claude Code reports each running background task (a subagent, a teammate, a workflow) as its own OSC 7501 record. zellij kept those records but showed only the most urgent, and `done` outranked `working`. So a session whose turn had ended read `idle` while its subagents still ran.

`list-agents --json` now carries `state_working`: how many of the pane's records say `working`, its own record included. It is absent when zero. Claude does not report background shell commands, so they are not counted.

### `action watch` reports `pane_changed`

```
{"event":"pane_changed","pane_id":"terminal_3","handle":"sunny-otter","tab_id":1,"title":"cargo test","program_title":null,"pane_cwd":"/src/app","pane_command":"/bin/zsh","terminal_command":null,"command_state":"running",...,"seq":12,...}
```

- Sent when a pane's `title`, `program_title`, `pane_cwd`, `pane_command`, `terminal_command`, `command_state`, `last_command_exit_code`, OSC 7501 state or `tab_id` changes. A pane moved to another tab is a `pane_changed` with the new `tab_id`.
- At most one line per pane per second, with the latest values. The first change after a quiet second goes at once, and the last one is never lost.
- The field names are `list-panes --json`'s. The snapshot does not carry them, so read `list-tree` once after `synced`.

A controller can now follow renames, `cd` and title changes from the stream instead of polling `list-tree`.
