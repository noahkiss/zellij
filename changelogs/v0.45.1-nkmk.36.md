# v0.45.1-nkmk.36

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the commit taken in nkmk.22
- **Range:** `v0.45.1-nkmk.35..rc/nkmk.36`
- **Released:** TODO: release pending

This release brings back a closed pane with its agent's resume line at the prompt.
A config written for a newer build now loads with warnings instead of failing.
The binary keeps the agent-session hook script current.
Three fixes cover Full Disk Access on macOS 27, prefilled restores and a noisy watchdog.

## Added

### Reopen a closed pane

The server remembers the last 10 closed terminal panes of each session, in memory only.
`Ctrl p u` brings back the newest one in its old tab, stacked, in its old directory and with its old handle when that is free.

| What closed | What comes back |
|---|---|
| A coding agent | A shell with the agent's bare resume pasted at the prompt, not run: `claude --resume <id>` |
| A command | A shell with the command line pasted at the prompt |
| A shell | A shell in the same directory |

The resume uses the session the agent held when it closed, the same one a restore uses.
A tab that is gone comes back as a new tab under its old name.
A pane whose process exited on its own is kept only when it was an agent or a command.

```
zellij action reopen-pane                 # the newest closed pane
zellij action reopen-pane --handle NAME   # one pane by its handle
zellij action reopen-pane --list [--json]
```

The keybind bar shows `reopen`.
MCP `zellij_create` takes `reopen="last"` or a handle.
Bind it elsewhere with the `ReopenPane` action:

```kdl
pane {
    bind "r" { ReopenPane; SwitchToMode "Normal"; }
}
```

The default plugins are rebuilt for the new plugin action.
A third-party plugin built earlier and reading keybinds can misread the `u` bind until it is rebuilt.

### `list-panes --json` names a prefilled restore

With `resurrect_commands "prefill"`, a restored agent pane is a shell with its resume pasted at the prompt.
`prefilled_command` now carries that line, from the moment it is pasted until the first input reaches the pane or the shell starts a command.
`restored_from` marks every restored pane and cannot tell them apart.

### The binary keeps `agent-session.sh` current

`zellij setup --agent-hooks --write` writes `~/.config/zellij/agent-session.sh` from this build.
`zellij session doctor` reports a missing or stale script, and `--fix` rewrites it.
Doctor tells an older build's script apart from local edits.
The claude hook now runs `agent-session.sh claude start` and `claude context` on SessionStart, and `claude end` on SessionEnd.
`agent-sessions register` merges fields, so a second register in another hook is harmless.

## Changed

### A setting this build does not know warns and is skipped

The whole config is tolerant: keybinds, modes, actions, key names, option values, `ui`, `web_client`, themes and plugin permissions.
An unknown name or value warns with its file and line, and the config still loads.
A bind with an unknown action is dropped whole.
An unknown option value falls back to its default.
`zellij setup --check` prints each warning and still reports the config as well defined.

A malformed known setting still fails: a wrong type, bad syntax, a known action with bad arguments.
An unknown `pane_privacy` value fails closed for that rule only: it takes the strictest known value.

A machine on an older build keeps its strict parser.
The oldest build in the fleet still decides when a new setting can go into a shared config.

## Fixed

- **Full Disk Access on macOS 27.** macOS 27 has no per-user `~/Library/Application Support/com.apple.TCC`. Every probe now opens the system directory `/Library/Application Support/com.apple.TCC`, so doctor, the keybind bar's `fda` reading and the TCC badge answer again.
- **A quiet watchdog.** The init system's own `session up` prints nothing on a healthy session. Before, it wrote an `already running` line on every tick.
