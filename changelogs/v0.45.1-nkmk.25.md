# v0.45.1-nkmk.25

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the one commit
  taken ahead of the next base in nkmk.22
- **Range:** `v0.45.1-nkmk.24..main`
- **Released:** 2026-09-29

The nkmk.24 rollout showed a Mac with a superseded server and no red `zj` badge in the tab bar,
while every command-line surface flagged it. Three independent reviews of the build-identity code
found the same family of bug in seven places. This release fixes all seven. Nothing crosses a
contract; no `ls --json` field changes shape.

## Fixed

### The tab bar's superseded-build badge lights on every platform

The server asked "am I superseded" by re-reading the file at its own path and comparing it with
itself. On Linux the pin refresh left a " (deleted)" suffix on that path, which happened to answer
the question; on macOS the path exists again and holds the new build, so the answer was always
"no". The third rule looked for a newer build on `PATH`, but the launcher puts the pin directory
first, so it found the pin. The server now records the build it started as, with its socket, before
anything can write over it, and answers from that: the start path is gone, or was written after
the socket was bound, or holds a different build, or a different build sits past the pin on
`PATH`. A session started by typing `zellij` no longer loses the badge at the next pin refresh.

### A server whose executable is gone reads as replaced, not unknown

```
$ zellij ls --json | jq '.[0] | {server_build, server_exe_replaced}'
# before, on a Mac after `brew uninstall zellij-nkmk-rc`
{"server_build": "unknown", "server_exe_replaced": null}
# after
{"server_build": "different", "server_exe_replaced": true}
```

Only Linux's " (deleted)" suffix set the replaced flag. A path that no longer exists is the same
proof and now counts on every platform, so an RC server left behind by the proof runbook is
visible to `ls --json`, the stderr warning and doctor.

### Doctor's `build` line says "cannot tell" when it cannot tell

`build_mismatch_warning` is silent for "same" and for "unknown", and doctor turned both into
"the running server is this build of zellij". Unknown, and a server whose identity cannot be
read, are now their own Needs-you line, in the words the Full Disk Access probe uses when it
cannot answer.

### Doctor run from the pin looks past the pin

With the pin directory first on `PATH`, a doctor run from a pane resolved to the pin and compared
the pin with itself: "was made from this build", while a newer keg sat installed and unused. Run
from the pin, doctor now finds the first `zellij` on `PATH` that is not the pin and reports
"holds an older build than the one installed at <path>", with the restart to run from there. The
note that `--fix` reaches the pin no longer claims so when doctor is the pin.

### Unit drift is judged against what was recorded, not against who is asking

```
$ ssh a-mac zellij session status mysession
# before
drift     ~/Library/LaunchAgents/dev.zellij.session.mysession.plist is NOT what this config would write now
# after
drift     none - the installed unit is what this config would write
```

The drift check re-rendered the unit from the calling shell's `PATH` and the caller's state
directory, then compared bytes. Any shell whose `PATH` differed from the one that ran `session
enable` saw drift, and following the advice recorded that shell's poorer `PATH` into the unit.
The comparison now reads `PATH` and the launchd log paths back from the installed unit, the way
`XDG_STATE_HOME` already was, so only a change this config would make reads as drift. Doctor and
`status` name the key that differs, and an explicit `session enable` that rewrites a unit prints
what changed.

### `zellij mcp` survives an upgrade on Linux

Every tool call ran `current_exe()`, which on Linux reads "<path> (deleted)" once the pin is
renamed over, so each call failed with "No such file or directory" until the harness restarted
the server. The same fallback spawned a new server for a client with no pin. Both now strip the
suffix and, when the file is gone, take the first `zellij` on `PATH` with the same name.

## Added

### `session status` gains a `build` line

```
build     'mysession' runs a different build from this binary
```

`status` reported unit, load, pin, drift and running, and nothing about the build. It now runs
the same comparison doctor does. A different build fails the exit code; "cannot tell" does not.

## Operator notes

- **Nothing to do on a Mac beyond the usual upgrade.** The badge fix takes effect for the NEXT
  upgrade: a server started on nkmk.25 shows the badge when nkmk.26's pin refresh lands.
- **A doctor or status run over SSH now agrees with one run from a pane.** If a machine reported
  unit drift before this release, re-check it; the drift was almost certainly the caller's PATH.
- **Nothing crosses a contract.** `ls --json` gains no field; `server_exe_replaced` is set in one
  more case.
