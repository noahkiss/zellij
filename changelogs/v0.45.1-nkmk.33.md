# v0.45.1-nkmk.33

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the one commit
  taken ahead of the next base in nkmk.22
- **Range:** `v0.45.1-nkmk.32..main`
- **Released:** 2026-10-12

zellij now answers the Program Status Protocol (`OSC 7501`), so Claude Code and pi report what
they are doing, and `list-agents` shows it: per session, across every session, or as a stream.
`action show` and the MCP `zellij_show` open an image viewer in a floating pane, and an image
reaches the terminal zlib-compressed. `session enable --dry-run` prints the unit it would write.
`zellij_wait_for until=ready` waits for the command just typed to finish. Four fixes ride along:
a new session never inherits an agent's identity, a pin replaced outside zellij reads as
replaced, `doctor --fix` from a release candidate leaves an anchored pin alone, and the opencode
hooks serve v1 and v2. Nothing crosses a contract.

## Added

### Program state on `list-agents`, from `OSC 7501`

```
$ zellij action list-agents --json
[{"handle":"bashful-dawn","kind":"claude",...,"state":"blocked","state_kind":"question",
  "state_app":"claude-code","state_msg":"answer: Pick red or blue? (Red · Blue)",...}]
```

Every pane answers the `OSC 7501 ; ?` query and keeps the reports, as the spec says: one record
per id, the most urgent surfaced (blocked > error > done > working > idle). A new prompt and a
program's exit drop `working`, `blocked` and `idle`. A `done` or `error` result stays until the
next program starts in the pane: a command start (`OSC 133;C`) after a prompt, or a new program's
`OSC 7501 ; ?`. Claude Code (2.1.295+) and pi send reports
once the query is answered; codex gets them from a hook (`agent-session.sh codex state`).

- `list-panes --json` and `list-agents --json` rows gain flattened keys, absent when nothing was
  reported: `state`, `state_kind`, `state_app`, `state_title`, `state_msg`, `state_progress` and
  `state_at` (epoch ms).
- The `list-agents` table gains a `STATE` column.
- Capability: `program-status-osc`. The state lives on the CLI-only row: no `PaneInfo` field, no
  plugin API change.

### `list-agents --all-sessions` and `--watch`

- `--all-sessions` lists the agents of every live session, with a `session` key and a `SESSION`
  column.
- `--watch [--interval-ms N]` prints NDJSON: the current agents first, then an `agent` line when
  an agent's handle, kind, id or state changes, and a `gone` line after two looks without it.
- Capabilities: `list-agents-all-sessions`, `list-agents-watch`.

### `list-clients --json` names the rootshell tab

A client attached with `LC_ROOTSHELL_PANE` set carries `"rootshell_pane": "<uuid>"` on its row.
The value travels in the host-terminal map every attach already sends. Capability:
`client-rootshell-pane`.

### `action show` and `zellij_show`: an image viewer in a floating pane

```
$ zellij action show screenshot.png shots/*.png
pane_id: terminal_7
handle: brave-heron
```

- The viewer (`zellij view-images`) draws with kitty graphics when an attached terminal can, and
  with 24-bit half-blocks when none can. `--mode auto|kitty|blocks` picks.
- Left/Right, h/l, Space and PgUp/PgDn flip; Home/End jump; q, Esc or Ctrl+c close.
- Reads PNG, JPEG, GIF and WebP, in-band: the pixels travel in the terminal stream, so a client
  over ssh sees them.
- MCP `zellij_show` runs it and returns the handle. The MCP surface is nine tools.
- Fixed with it: a new floating pane now takes the tab's kitty and sixel support, as every other
  pane does.

### An image goes to the client zlib-compressed

The server re-sends each image to every attached terminal. It now sends `o=z` when zlib is
smaller: a 410x520 screenshot crop went from 1,140,720 bytes to 277,554.

### `session enable --dry-run`

`session enable -n|--dry-run` prints the binary the unit would run, what would happen to the pin,
where the unit's `PATH` comes from, each file and what would change, the init-system commands,
then every file in full. It writes nothing and exits 1 when `enable` would refuse.

### `zellij_wait_for until=ready` waits for the command just typed

A prompt counts only when the shell drew it after the last input typed into the pane. So
`action wait --for ready` right after typing a command waits for that command to finish. A pane
nothing was typed into answers as before, so `--wait-ready` and `zellij_create` are unchanged.
`list-panes --json` carries `"input_since_prompt": true` while that is so.

## Fixed

### A new session never inherits an agent's identity

A session started from an agent's shell passed `AGENT_SESSION_ID`, `AGENT_KIND` and the harness
session variables to every pane, so each agent in it was named after its creator. The client now
drops them when it spawns a server: `session up`, `restart`, `attach --create` and `zellij -s`.

### A pin replaced outside zellij reads as replaced

A build copied over a stamped pin read as current. A `<pin>.pin-identity` record now names the
file zellij wrote. `session status` reports a replaced pin and exits 1, `doctor --dry-run` notes
it, and the next pin write refreshes it. A pin from nkmk.32 has no record and is trusted as before
until its next refresh.

### `doctor --fix` from a release candidate leaves an anchored pin alone

The deferred signing refresh skipped the RC check. Every door to the pin now asks one predicate.
`ZELLIJ_PIN_ALLOW_RC=1` lets a candidate write a pin outside the account's home, for a scratch
proof; never the real one.

### The opencode hooks serve opencode v1 and v2

`zellij setup --agent-hooks` writes one file per surface that both versions load. The TUI
package moves to `~/.config/opencode/plugins/agent-session/`, and v1 names it in `tui.json`.

## Operator notes

- **codex state needs the new hooks.** Re-run `zellij setup --agent-hooks` and install the codex
  snippet. Claude and pi need nothing.
- **An RC proof's `doctor --fix` on a scratch pin needs `ZELLIJ_PIN_ALLOW_RC=1`.**
- **The pin identity record appears at the first refresh** after this release.
- **Nothing crosses a contract.** A restart picks the changes up.
