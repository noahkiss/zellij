# v0.46.0-nkmk.46

- **Upstream base:** unchanged — the `v0.46.0` release tag (`aedee21cb`)
- **Range:** `v0.46.0-nkmk.45..v0.46.0-nkmk.46`
- **Released:** 2026-11-25

This release makes agent messages harder to lose, and turns several fixed timings into config keys whose defaults keep today's behaviour.

## Added

- **`agent_message_expire`** sets how long a held agent message waits before it expires: a span such as `"4h"`, or `"never"`. The receiving machine's config decides. The default stays 30 minutes. `zellij_send` no longer advertises 1800 as its default, so an agent that gives no `expire_s` gets the configured value. Capability: `agent-message-expire`.
- **Expiry notices reach every sender.** A message that expires undelivered now tells a sender in another session, or on another machine, not only one in the same session. A notice to another machine goes over ssh, to a host listed in `remote_hosts` only, with one try. `send-message --host <host>` is the new CLI route it uses.
- **A late message names its age.** A message delivered 2 minutes or more after it was queued carries `queued 47 min ago` in its envelope, so the receiver can weigh a stale instruction.
- **Delivery receipts.** `send-message --receipt` (`zellij_send receipt`) tells the sender when a held message is finally typed in: `message 12 to work/sunny-otter delivered after 14 min`. A message delivered at once sends no receipt, because the send result already says so. A receipt costs the sender a turn; `message-status <id>` is the polling alternative.
- **`session_service { upgrade_restart_clientless_for "15m" }`** makes the upgrade restart wait until a session has had no client for that long, so a short detach does not land a restart on a running build or ssh session. The default `"0s"` keeps today's behaviour.
- **`remote_hosts { connect_timeout "5s"; fleet_timeout "10s" }`** sets the ssh connect timeout and the fleet overview's per-host limit. The send and notice deadlines follow from them.
- **`agent_startup_grace`** (default 60s) sets how long a new agent has to report a state before a message to it is refused as `no_state`.
- **`agent_message_quiet`** (default 5s) sets how long a pane must have had no key before a message goes in.
- **`mcp_wait_timeout`** (default 300s) sets `zellij_wait_for`'s wait when the caller gives none, for MCP clients that cut a request off sooner.
- **`pane_frame_handle false`** hides the pane handle on frames. Handles stay in `list-panes` and everywhere else. A reload applies it.

## Upgrading

- The message, receipt, guard and frame changes are in the server: a session picks them up when it restarts onto this build. `session status` reports the restart as needed.
- `send-message --receipt` adds field 9 to the send-message request. An older server ignores it and sends no receipt; nothing else changes.
- Every new key is optional. nkmk.45 warns about each new top-level key and ignores it, and an older `zellij mcp` warns about the new `remote_hosts` entries and keeps 5s and 10s. Seed the keys in a shared config once every machine runs this build.
