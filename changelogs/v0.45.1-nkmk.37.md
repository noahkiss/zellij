This release names the version each live session's server runs in `ls --json`.
The watchdog warns about a superseded build once, not on every tick.

## Added

### `ls --json` names the running server's version

Each live row gains `server_version`: the version the server runs, as its `zellij --version` prints it after "zellij ".
`ls` never runs the server's binary to ask. The value comes from one of two places:

| Case | Where `server_version` comes from |
|---|---|
| `server_build` is `same` | The listing binary's own version |
| `server_build` is anything else | The `server-version` stamp in the session's session_info folder |
| Neither applies | The key is absent |

A server writes the stamp as it starts. The stamp holds its pid and its version.
`ls` trusts the stamp only when that pid serves the session now.
So a stamp an earlier server left under the same name never counts.
A server that exits cleanly removes its stamp. Snapshots neither hash nor copy it.

A server older than this release writes no stamp.
So a newer `ls` against an older server reports `server_build` "different" and no `server_version`.

## Fixed

- **A watchdog that warns once.** While a restart was owed, every watchdog tick wrote the four-line build-mismatch warning to stderr. One Mac's error log held 25,615 copies. The init system's own `session up` now records the build pair it warned about in `<state dir>/build-warned/<session>`. It stays silent until the running server or its own binary changes. A `session up` from a shell warns every time, as before. `session status` and `session doctor` are unchanged.
