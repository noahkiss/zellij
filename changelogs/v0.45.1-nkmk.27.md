# v0.45.1-nkmk.27

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the one commit
  taken ahead of the next base in nkmk.22
- **Range:** `v0.45.1-nkmk.26..main`
- **Released:** 2026-10-05

Two fixes to the Mac upgrade path. `session doctor --fix` re-signed a pin with a different
certificate than the one the grants name, and a later dry run said the grants still held. And
`session enable` over SSH shrank the launch agent's `PATH` at every release. Nothing crosses a
contract; no `ls --json` field changes shape.

## Fixed

### Doctor keeps the certificate the grants name, and remembers a switch

On a Mac whose pin was signed with the fork's own minted certificate, adding an Apple Development
identity to the keychain made the next `doctor --fix` re-sign the pin with the Apple one. Every
grant (Full Disk Access, Accessibility, Screen Recording) then had to be made again. Doctor said
so once. The next dry run said the grants "still hold", because nothing recorded the switch.

- When the requirement the grants were made against names an offered certificate by hash,
  doctor signs with that certificate only. A refusal from it is a `Needs you`, not a fall to
  another certificate.
- A switch that the new signature does not satisfy writes the old requirement to
  `~/Library/Application Support/zellij/signing/regrant-owed`. Every later run reports the
  re-grant as owed:

```
Needs you
  signing   <pin> is signed as org.zellij.nkmk, and the grants were made against another requirement
            now:     designated => identifier "org.zellij.nkmk" and anchor apple generic and ...
            granted: designated => identifier "org.zellij.nkmk" and certificate leaf = H"..."
            1. re-grant Full Disk Access, Accessibility and Screen Recording for <pin>
            2. `zellij session doctor --fix --regranted`, so doctor records it as made
            3. THEN `zellij session restart`
```

- The record clears on `zellij session doctor --fix --regranted`, or when the pin satisfies the
  recorded requirement again. Doctor tests that with `codesign --verify -R=<requirement>`, the
  test macOS makes when it reads a grant.
- The same test decides whether a change of requirement owes a re-grant. A change whose new
  signature still satisfies the old requirement no longer asks for one.

### `session enable` from a thinner shell keeps the recorded `PATH`

```
$ ssh mac zellij session enable mysession
      kept the installed PATH: this shell's PATH adds nothing to it and lacks 2 directories that exist
        /usr/local/bin
        /Users/user/.rbenv/shims
      to record a new PATH, run `session enable` from a shell that adds to it
ok    service for 'mysession' is already enabled
```

A non-interactive SSH shell has a thinner `PATH` than a terminal, and `enable` recorded it. One
Mac's launch agent went from 17 `PATH` entries to 13 at every release, until an `enable` from a
terminal put them back. `enable` now keeps the installed unit's `PATH` when this shell's `PATH`
adds nothing to it and drops a directory that still exists. Every other shell re-records as before.
Drift reads the `PATH` back from the unit, so a kept `PATH` compares as current.

## New

- `zellij session doctor --regranted`. With `--fix`, it records an owed re-grant as made. With
  `--dry-run`, it reports what it would clear and clears nothing.

## Operator notes

- **A pin switched before nkmk.27 carries no record.** This build sees no switch on such a pin and
  reports no debt. If its grants were made against the old certificate, re-grant for the current
  one by hand.
- **"kept the installed PATH" over SSH is expected.** To drop a directory that still exists on
  purpose, `session disable` and then `session enable` from the shell that lacks it.
- **Nothing crosses a contract.** One new flag on `session doctor`; no config key, no new
  subcommand, no `ls --json` change.
