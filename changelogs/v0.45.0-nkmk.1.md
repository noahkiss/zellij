# v0.45.0-nkmk.1

- **Upstream base:** `f42ca3c79` on upstream `main` (workspace version `0.45.0`, 64 commits past
  the `v0.44.3` tag)
- **Range:** `f42ca3c79..main` (17 curated patches; the tag adds the plugin rebuild, two doc
  commits and the version bump)
- **Released:** 2026-08-10

The fork moves off the `v0.44.3` tag and onto upstream `main`. Nothing here is a new feature: the
patch set is the one nkmk.10 shipped, rewritten to fit 0.45. The counter restarts at 1 because the
upstream version moved, not because the fork lost anything.

**Read the breaking-change section before upgrading if you build plugins against this fork, or if
you drive it from a CLI built elsewhere.**

## What changed in the fork

### The patch queue is now a curated patch set

nkmk.10's `main` was 129 commits on the tag, most of them fixups to earlier patches. Replaying that
through an upstream rebase was not worth doing a second time, so the series was rebuilt as **17
patches, one squashed commit per feature**, on `git rebase --onto upstream/main`. A patch upstream
later absorbs can still be dropped whole; a fixup no longer travels as its own commit.

The full ledger is [FORK.md](../FORK.md), which now records the upstream base SHA and the rebase
recipe. `git log --oneline f42ca3c79..main` is the list.

### `top_only` is a `pane_frame_style` value, not an option

Upstream 0.45 added `pane_frame_style` with `full`, `titles` and `none`, and made `titles` the
default. The fork's old `ui { pane_frames { top_only true } }` override is **gone**. The behaviour
returns as a fourth value of upstream's own setting:

```kdl
pane_frame_style "top_only"
```

It behaves as `titles` with two differences: the title row is filled edge to edge with `─` whether
or not the pane is stacked, and no separators are drawn between panes. Everything that reads
`pane_frame_style` — the CLI action, the keybinding, the plugin API — accepts it.

A `config.kdl` still carrying `top_only true` is not an error; an unknown key is ignored. It simply
stops doing anything, so move it.

### Fixes carried in the rebase

- `move-tab --to-index` places a tab at an absolute index again, against 0.45's reordering code.
- The `PaneInfo` stack fields (`stack_id`, `index_in_stack`, `is_expanded_in_stack`) are correct
  against 0.45's new stack-list rendering.
- `delete-session --all --force` deletes live sessions again. Its candidate list came from a
  serialized-layout scan, which a young live session is not in yet, so it silently deleted nothing
  and exited 0. Live names are now taken from the session list directly, and without `--force` they
  are named and the command exits 1 rather than claiming success.

## Breaking changes

**Plugin API tags were renumbered.** Upstream took the numbers the fork had been using, so the
fork's own additions moved out of the way:

| Addition | Was | Now |
|---|---|---|
| `PluginCommand::DetachClients` | `CommandName 215`, payload `164` | `CommandName 229`, payload `172` |
| `PluginCommand::ListSnapshots` | `216` | `230` |
| `PluginCommand::RestoreSnapshot` | `217`, payload `165` | `231`, payload `173` |
| `Event::ListSnapshots` | `EventType 47`, payload `41` | `EventType 50`, payload `44` |
| `Event::SnapshotRestoreFailed` | `48`, payload `42` | `51`, payload `45` |

`PaneFrameStyle::TopOnly` is tag `100`, deliberately far from the next number upstream would take.

What this means in practice:

- **A plugin built against nkmk.10 must be rebuilt.** An old binary sending `215` now reaches a
  different command. The bundled plugins are rebuilt in this release; yours are not.
- **A CLI and a server of different vintages must not be mixed.** The client/server contract also
  moved under 0.45. Upgrade the binary and restart the session rather than leaving a stale `zellij`
  on `PATH`.

## What upstream brought

The parts of the 64-commit upstream delta most likely to be noticed:

- **`pane_frame_style`** — frames are now a named style, and the default changed from full frames to
  `titles`. This is why the fork's `top_only` became a value rather than an override.
- **Stack list rendering** — collapsed stack members are drawn as a list. One consequence worth
  knowing when reading `list-panes --json`: a collapsed member reports `is_suppressed = true`. That
  is upstream's accounting of what is drawn, not a fork behaviour — read `stack_id` and
  `index_in_stack` for membership.
- **Kitty image protocol support**, and the sixel aspect-ratio and opacity fixes.
- **Web client work** — PWA support, mobile layout, nested sessions.
- **Mouse handling improvements**, including OSC 133 command-output selection on triple click.
- **An integration-test suite** (`zellij-integration-tests`), a new workspace member.

## Known, not a regression

The session manager's client list (`Ctrl+l`) comes up empty, while `zellij action list-clients`
answers correctly. The cause is upstream's own `Event::ListClients` path — the requesting plugin's
pane is removed from the layout before the focus-derived client list is built. It behaves
identically on nkmk.10, on stock upstream and on this release, so it is a standing bug rather than
a regression from the sync. Not fixed here.
