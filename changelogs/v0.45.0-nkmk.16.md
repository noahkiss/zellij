# v0.45.0-nkmk.16

- **Upstream base:** the `v0.45.0` tag (workspace version `0.45.0`) — moved up from `98a083707`,
  which had been the base since nkmk.13
- **Range:** `v0.45.0-nkmk.15..main` (20 commits)
- **Released:** 2026-08-21

The largest release the fork has cut, and it has two themes. The first is the detached session:
a session nobody is attached to can now make a tab that holds panes, reload a plugin, and recover a
pane whose plugin never loaded — three separate refusals that all came down to code asking for a
client it did not need. The second is the session lifecycle on a real machine, where sixteen
separate fixes land across the systemd and launchd generators, the signing ladder, the doctor's
reporting, and the snapshot archive. Around those: pane handles are a fixed width, a failed plugin
leaves a mark something outside the server can read, and `ls --json` finally answers which binary
each session is running.

## Added

### A detached session sizes its own tabs

A tab is built by applying a layout, and a layout needs a size. Sizes lived in `client_sizes`,
keyed by client, so the last client to detach took the session's only size with it — every tab built
afterwards came out 0×0, and a 0×0 tab holds no panes. For two releases `new-tab`, `new-tab
--layout`, `new-pane --new-tab`, `go-to-tab-name --create` and `break-pane` refused rather than
making the empty ghost tab.

The session now keeps a size of its own, seeded from the size it started with and thereafter
tracking the last real client, so a detached session lays out against the terminal it last had. The
refusal is gone. `go-to-tab-name` is the one place the two halves part company: `--create` is
answered, and a bare `go-to-tab-name` — which is only a focus move, with no focused tab to move —
still exits 2.

### `managed_session`: the init system owns one session, and every create defers to it

```kdl
session_service {
    managed_session true
}
```

Set, the unit for `session_name` becomes unconditional: it is installed and kept current by whatever
is about to need it, so `session enable` stops being the step somebody has to remember. Every path
that would *create* that session hands the creation to the unit instead — `launchctl kickstart` on
macOS, and on Linux the twin it never had, `systemctl --user start` on the generated `Type=oneshot`
service. The recursion guards are the init systems' own records, launchd's `XPC_SERVICE_NAME` and
`/proc/self/cgroup` compared by whole path segment, so a unit cannot be asked to start the unit it
is.

The name is matched whole against the configured `session_name`, so an ad-hoc `zellij -s scratch`
is untouched. Unset, nothing changes for anybody.

### `watchdog_interval_secs` retimes the watchdog on both platforms

```kdl
session_service {
    watchdog_interval_secs 15
}
```

Whole seconds, at least 1. macOS could already be retimed through the `launchd { keys { … } }`
hatch, since `StartInterval` is a plist key; Linux could not, because the timer's `OnBootSec=` and
`OnUnitActiveSec=` came from a constant and the `systemd` sub-block writes into the *service*, not
the timer. One neutral key now sets both, because the systemd timer exists precisely so that the two
platforms tick together.

On Linux it writes both timer directives, and the service file's comment quotes the same number. On
macOS it is the *default* for `StartInterval`, so an explicit `StartInterval` in the launchd extras
still wins — that key names one platform and is the more specific of the two. Unset, every generated
file is byte-identical to what it was.

### `SessionInfo.plugins` says which plugins a session is running

The field, its protobuf tag and both conversions have been there all along, and it was empty in
every answer anyone could get to. Two independent gaps did it: nothing joined the plugin list to the
session metadata before the file was written, and the KDL codec dropped the field outright. So a
session could be told its own plugins by an in-memory patch-up after the read, and every *other*
session on the machine came back claiming to run none — meaning the `Event::SessionUpdate` a plugin
subscribes to, which carries every session, was right about exactly one of them.

Metadata written by an earlier build has no `plugins` node and reads back as a session running none
rather than as a parse failure. Nothing about the plugin contract changed.

### A plugin that failed leaves a durable mark

A command pane that fails is marked `error:exit 7` and stays marked; a plugin pane that failed was
not marked at all. It printed `ERROR IN PLUGIN` into its own body and flashed its frame red for a
second, and neither is a mark — to `list-panes`, a session with a broken plugin looked exactly like
a session without one.

It now gets the same note: `error:plugin failed`, on the frame and in `list-panes`, `list-tree` and
`PaneInfo`. It is cleared when the *next attempt starts*, which is where a re-run command pane drops
its `exit 7`, so a reload that fails again re-marks the pane a moment later and a reload that hangs
leaves no stale claim of failure standing.

### `ls --json` says which binary each session is running

A server keeps the binary it started with, so a fleet drifts: upgrade every machine and the sessions
already up stay where they were. Live entries now carry `server_exe`, `server_build_id` (hex of the
Mach-O `LC_UUID` or the GNU build-id), `server_build` (`same`/`different`/`unknown` against this
binary) and `server_exe_replaced` where Linux says the running file was written over in place.

Zero protocol cost by design — it is read from the OS by pid on the side that runs `ls`, so there is
no `SessionInfo` field and no contract message. No version string, deliberately: a listing must not
execute whatever those paths point at. The build id is also the better answer, proved while testing
this, where two sessions reporting the same `zellij --version` were correctly told apart.

## Changed

### Pane handles are a fixed width, and no two live panes share a word

Every generated handle's two words now sum to 11 letters, so a pane frame's handle no longer changes
width from one pane to the next. A handle is drawn from a filtered `(adjective, noun)` pair space
built once; the vendored word lists grew to 504 adjectives and 594 nouns so every 3–8 letter length
has a same-sum partner, giving 58,057 generatable pairs.

No two live panes share a *word* either, not just a whole handle. A fresh draw that repeats either
word of a live or reserved handle is refused, with a three-rung fallback ladder — random rerolls, a
deterministic sweep of the pair space, then a bounded numeric suffix only if the whole space is
refused. A chosen or restored handle is still taken verbatim.

This moved the deterministic `ZELLIJ_SEQUENTIAL_PANE_HANDLES` sequence, so 275 `zellij-server`
snapshots were refreshed with it.

## Fixed

### The CLI stops hanging on a session that answers to no server

`connect_to_server` retried every 50 ms forever. That is right while a server it just asked to spawn
is still binding its socket, and wrong for a session that answers to no server at all — a crashed
process, a socket file left behind, a name that was never coming up. Every verb against such a
session hung instead of failing, `action` and `subscribe` and `attach` alike.

It now gives up after five seconds with `session '<name>' is not running (or its server is
unreachable): <io error>`, and each CLI entry point reports that on stderr and exits non-zero. This
is a different timeout from `session up`'s own `SERVER_APPEARANCE_TIMEOUT` wait for a server it just
spawned.

### Sixteen fixes across the session lifecycle, signing and snapshots

Sessions and the init system:

- The systemd generator **quotes** `ExecStart=` and `Environment=`. Neither was quoted and both are
  split on spaces, so one space in a path truncated the exec line and discarded the rest of `PATH`
  — after which every layout `command` pane, `zellij run --` and `copy_command` failed with
  "command not found" beside an interactive pane that worked.
- `unit_drift` reads `XDG_STATE_HOME` back out of the installed unit instead of regenerating it from
  the calling process's environment, which reported drift on a correct install and, if followed,
  rewrote the unit without the state root.
- `ps` is asked with `-ww`. BSD `ps` cuts every line to the terminal width and the socket path is the
  last field, so a cut line made `servers_for_session` return nothing for a healthy session and
  `session status` print `running no`.
- `server_exe_for_interactive_launch` consults the installed unit and returns `None` on a
  `PinState::Mismatch`, so a session is never served from a pin the launcher does not run.
- `session down` takes the up-lock, so removing a session no longer races the watchdog that puts it
  back.
- `session disable` finishes over a half-install: it unloads only what is on disk and removes the
  files even when the unload failed.
- `session enable` makes the launchd log directory *before* its already-enabled short-circuit can
  return — launchd will not run a job whose `StandardOutPath` it cannot open.

Signing:

- The keychain ACL grant is scoped with `-l <common name>`. `security set-key-partition-list -s`
  selects every signing key in the login keychain, so doctor was rewriting the partition list of an
  Apple Development key sitting beside ours, and Xcode began raising key-access dialogs on builds
  that used to be silent.
- A minted certificate that then failed to import is kept and reported, rather than discarded along
  with the findings list that said it had been minted.
- A keychain that will not answer is no longer read as one with no certificates. `find_identities`
  folded both failure shapes of `security find-identity` into an empty list, so a locked login
  keychain read as "no Apple certificate" and took doctor to the one rung that mints, over an
  identity the machine already held.

Doctor:

- The pane probe reports the client's own failure, with `try_wait` in the loop and stderr kept,
  instead of charging every fast failure the full five seconds and calling it "did not answer in
  time".
- The Linux start check stops reporting on a systemd it never reached. `LoadState` is consulted
  first, because systemd answers `Result=success` for a unit it has never heard of; and a `systemctl`
  that ran and failed is reported as "could not ask systemd" rather than read as "has not run yet".
- A dry run's "would sign `<pin>`" is a `Changed`, not `Already correct` — reassurance about the
  exact thing that was broken.
- `session restart` opens both `restart.log` handles in append mode. Only one of the two followed
  the end of the file, so stdout's next write went down at its own lower offset and ate the front of
  a stderr line.

Snapshots:

- `archive_session_info_folder` returns an `ArchiveOutcome`, so `snapshot import --prune-source` no
  longer reads "archiving is off" as "already archived" and deletes a source it never archived.

Four more papercuts:

- `terminal_title_template`, `session_aliases` and the `snapshot_*` settings are `RwLock`s rewritten
  from `propagate_configuration_changes`, not `OnceLock`s that dropped every write after the first —
  so editing one and reloading the config works instead of needing the session recreated.
- `resolve_service_exe` falls back to scanning PATH for any entry that resolves here when the
  same-name probe fails, in PATH order then alphabetically so the unit stays byte-identical run to
  run.
- `close-pane --pane-id` resolves its target before the client prompts, so a miss exits 2 instead of
  asking first and reporting the miss afterwards.
- `install_pinned_exe` reads the pin's length and mtime before the copy and compares before the
  rename, so a run that would clobber a newer pin discards its signed temp and names the recovery.

### A plugin reloads in a session nobody is attached to

`reload_plugin_with_id` asked for a connected client and gave up when there was none, so the reload
worked from *inside* a session and not from outside one — backwards, since a detached session is
exactly where a plugin is edited and reloaded without a terminal in the way. Nothing about the
reload needs a client to be attached: the id is only the key the plugin's instance sits under in the
plugin map, and the instance already has one. A connected client is still preferred; the map answers
when there is none.

### Reload recovers a pane whose plugin never loaded

Fix the file, reload the pane. It bailed twice over, and the only way back was restoring the layout —
which throws the session's shape away to fix one pane. Both halves read the plugin map, and a pane
whose plugin failed to load is in no plugin map: `reload_plugin` missed it and the caller fell
through to *starting* the plugin, a stray second pane beside the broken one, while
`reload_plugin_with_id` bailed at the first thing it read off the running instance.

Both are answered from outside the map now. The failure record is searched by location, and a pane's
placement — size, tab index, cwd — is recorded when a load starts and kept current by resizes. A
running instance is asked first in every case. The config is rebuilt with
`PluginConfig::from_run_plugin`, which re-resolves the location, so the file that has since come back
is the one the reload loads.

### A failed remote plugin download no longer parks every later reload of it

A download failure returned before `execute_plugin_load`'s closure ever ran, and that closure is the
only thing that takes a `plugin_id` out of `loading_plugins`. `reload_plugin` checks that same set
before doing anything else, so a remote plugin that failed to download once was stuck refusing every
later reload of that location for the rest of the session — silently, no error, no retry.

### Pin state is reported when it changes

`SetFloatingPanePinned` and both pinned *toggles* mutated pin state and stopped — no render, no
`log_and_report_session_state`, unlike their CLI neighbours `set-pane-floating` and `set-sync-tab`.
`PaneInfo.is_pinned` stayed wrong for every subscriber until something unrelated dragged a report
along with it.

### `-s` reaches `attach` too

`zellij action` and `zellij subscribe` both take the top-level `-s` as the session they target;
`attach` never did. `zellij -s myname attach -c` silently ignored it and minted a fresh random name
instead, because clap does not reject an unused global flag. `attach`'s own positional still wins
when both are given.

## Operator notes

- **One-time unit drift.** The systemd generator now quotes `ExecStart=` and `Environment=`, so
  every installed unit's bytes change. The first `session status` or `session up` after upgrading
  reports drift and asks for a `session enable`. This is one-time and intended.
- **`session enable` keeps the recorded state root.** It now *keeps* the `XDG_STATE_HOME` recorded
  in the installed unit instead of overwriting it from the calling shell. To move the state root,
  run `session disable` and then `session enable`.
- **Linux `session doctor` may exit 1 where it exited 0.** With no unit installed, or no user bus,
  it now says so rather than reporting on a systemd it never reached. Scripts keying on the exit
  code will notice.
- **`session_service { managed_session true }` ships *with* this binary.** It is a nested key, and an
  older binary rejects the whole config on an unknown one. Do not seed it into a shared config
  before every machine has upgraded — unlike a new top-level key, this one cannot go out ahead of
  the code that accepts it. **`watchdog_interval_secs` is nested too**, and the same rule applies to
  it without exception.
- **A new interval needs `session enable` re-run on each machine.** Changing the config does not
  rewrite an installed unit; nothing does that on its own. `session status` reports the timer as
  drifted until the machine is re-enabled, which is the same behaviour as every other key in that
  block. On macOS re-enable after editing the interval too — launchd keeps the definition it was
  given, not the file it came from.
- **`zellij-mac-setup` refuses to run when it predates the installed binary** (exit 3). It expects
  `SCRIPT_FOR_RELEASE=0.45.0-nkmk.16`.
- **Two items need first-Mac confirmation at rollout:** the keychain ACL `-l` scoping and the doctor
  pane-probe behaviour. Both fail safe — the ACL grant grants nothing rather than the wrong thing if
  the label does not match, and the probe's refusal is a `Needs you`.

## Upgrading

- Macs: `brew upgrade zellij-nkmk`, then `zellij-mac-setup`, then `zjr`.
- Linux: `session enable` once after upgrading, to take the re-quoted unit.
