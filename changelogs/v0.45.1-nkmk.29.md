# v0.45.1-nkmk.29

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the one commit
  taken ahead of the next base in nkmk.22
- **Range:** `v0.45.1-nkmk.28..main`
- **Released:** 2026-10-05

Two follow-ups to nkmk.28's agent resume. An agent run as a command pane was recorded as its newest
child, so a restore dropped it. And `list-agents` named the session a claude pane started with, not
the one it holds after a `/clear`. Nothing crosses a contract; no `ls --json` field changes shape.

## Fixed

### A command pane is recorded as its own command, not its newest child

A pane can run an agent directly: a layout's `command "claude"`, or a restored pane after Enter.
Then the pane's own process is the agent, and the terminal names it as the foreground group.
Serialization treated that like an idle shell and recorded the newest child: an MCP server, a tool
shell, a `sleep`. In `"agents"` and `"prefill"` mode the filter then dropped the pane. In `"all"`
mode it came back running the child.

Serialization now asks about command and editor panes separately. When the terminal names the
pane's own process, the pane records that process's argv. Shell panes are asked as before.

| pane | recorded before | recorded now |
|---|---|---|
| `command "claude"` with MCP children | the newest child | `claude ...`, then the agent resume |
| an editor pane with a language server | the language server | the editor and its file |
| a shell, idle or running a job | unchanged | unchanged |

### `list-agents` names the session claude holds now

`AGENT_ID` for a claude pane came from `CLAUDE_CODE_SESSION_ID`, which only claude's children
carry, each frozen at its spawn. After a `/clear` it still named the first session. The walk now
reads Claude Code's record, `sessions/<pid>.json`, with the same code serialization uses, and
re-reads that one file each tick. A pane with no record keeps the variable's value.

## Operator notes

- **`"all"` snapshots change for command panes with children.** Such a pane now comes back running
  its own command, not its newest child.
- **The live pane list still asks the old way.** `list-panes` and `list-agents` can show a command
  pane's newest child, and give a `command "claude"` pane no `AGENT_ID`. Serialization is fixed;
  the live list is not.
- **The live id is read from the server's environment**, as in nkmk.28. A pane that sets its own
  `CLAUDE_CONFIG_DIR` keeps the variable's value.
- **Nothing crosses a contract.** No config key, no subcommand, no `ls --json` change. A restart
  picks the fixes up.
