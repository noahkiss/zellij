# v0.45.1-nkmk.38

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the commit taken in nkmk.22
- **Range:** `v0.45.1-nkmk.37..rc/nkmk.38`
- **Released:** TODO: release pending

This release lets an agent open a plugin pane in its own tab through the zellij MCP.
`zellij_create` now checks the pane before it reports that it typed a command.
`zellij action reload-template` gives every live tab the current tab template, so a new bar reaches a running session without a restart.

## Added

### `zellij_create run_in=plugin`: a plugin pane in the agent's own tab

`zellij_create` takes `run_in: plugin`. With it, `command` names the plugin to load: `file:/path/to.wasm`, `zellij:<name>` or an alias.
The new `plugin_config` parameter takes the plugin's configuration, one `key=value` per entry.

```json
{"run_in": "plugin", "command": "file:/tmp/bar.wasm", "plugin_config": ["data_file=/tmp/d.json"], "handle": "bar-test"}
```

The pane opens in the agent's own `-zj` tab, or in a new tab with `kind: tab`. It never takes the person's focus.
The answer carries the pane's handle, so `zellij_read_pane` can read what the plugin draws.
`kind: stacked` is refused, because the CLI cannot stack a plugin pane.

### `zellij action reload-template`: every live tab gets the tab template

```
$ zellij action reload-template                        # the configured default layout, read again
$ zellij action reload-template --layout ~/bar.kdl     # the tab_template of another layout
```

Add a bar plugin to the `tab_template` of `default.kdl` and run it. Every live tab gets the bar, and the session keeps running.

- Each tab gets the template's plugin panes, unless a pane in that tab already runs the same plugin. A second run starts nothing.
- Every existing pane is kept, with its process. The template's terminal slots never start a shell.
- No tab is closed, renamed or added. It needs no focused tab, so it works with no client attached.
- Without `--layout`, the server reads its configured default layout again from disk. A failed read prints why, exits non-zero and changes nothing.

`override-layout` could not do this. It closes every tab its layout does not list, renames the tabs it does list, and adds a stray shell to a tab whose first pane was started with a directory.

Limits: each tab's swap layouts become the template's. New tabs still come from the layout the session started with.
A stock server does not know the new action and changes nothing.

## Fixed

- **A plugin pane opens in the tab it was asked for.** `new-pane --plugin` with `--tab-id` or `--in-tab` opened the pane in the focused client's tab. With no client attached, it opened nothing.
- **`new-pane --plugin --new-tab` reports the plugin it opened.** It reported an arbitrary plugin of the new tab, often the template's status bar, and `--handle` named that bar.
- **`zellij_create` reads its pane back before it says `input_sent`.** `input_sent: true` meant only that the keystrokes were sent. A create now reads the pane's working directory before it types, and reports `pane_cwd` and `cwd_honoured`. After it types, it reads the pane for up to 2 seconds. When the pane shows neither the command running nor its text, `input_sent` is `false`, with a note to read the pane before typing again.
- **`zellij_wait_for` explains `timeout_s` against the client's deadline.** A wait answers just after `timeout_s`, and many MCP clients give up at 60 seconds. So `timeout_s: 60` always lost, and the caller got a request timeout instead of the bounded miss. The description now says to stay under the client's deadline and wait again. The 300-second default is unchanged.
