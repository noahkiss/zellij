# v0.45.1-nkmk.24

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the one commit
  taken ahead of the next base in nkmk.22
- **Range:** `v0.45.1-nkmk.23..main`
- **Released:** 2026-09-28

The third release of the day, and the first whose Docker e2e suite ran **before** the tag. Two
leftovers from the nkmk.23 proof, one line each, and one change to the release rule itself.
Nothing crosses a contract; no field, flag or key changes.

## Fixed

### Doctor names the config file it loads

```
$ ZELLIJ_CONFIG_DIR=/tmp/scratch/config zellij session doctor --no-fix mysession
# before
  config    ~/.config/zellij/config.kdl parses        # not the file it loaded
# after
  config    /tmp/scratch/config/config.kdl parses
```

The `config` line built its name from the default search while the load beneath it honoured
`--config-dir`, which is how `ZELLIJ_CONFIG_DIR` arrives. Under a scratch config dir doctor
reported the real config as the one that parsed. The name now follows the load's own order:
`--config`, then `--config-dir`, then the default search.

### A comment that was true until nkmk.23

`server_exe_replaced` on `ls --json` said only Linux could set it. Since nkmk.23 every platform
sets it when the file at the server's path was modified after the session's socket was bound. The
comment now says so. No behaviour changed.

## Changed

### A pull request proves the e2e suite before the release tag

`End to End tests` runs on a push to `main` and on a pull request, and on nothing else. A bare
branch push and an RC tag never trigger it, so nkmk.22 and nkmk.23 were each tagged with that
surface unproven and got their e2e result minutes later, on the `main` push. AGENTS.md's RC step
now says: open a PR from the branch when the RC tag goes up, and do not tag the release until the
PR's e2e run is green. The PR is never merged; `main` lands by fast-forward as before and the PR
is closed. This release is the first to follow it.
