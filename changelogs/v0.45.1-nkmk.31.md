# v0.45.1-nkmk.31

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the one commit
  taken ahead of the next base in nkmk.22
- **Range:** `25d1cd35f..main`. The series was condensed on 2026-10-06, so the `v0.45.1-nkmk.30`
  tag stays on the pre-condense branch; `25d1cd35f` holds the same tree plus two doc notes.
- **Released:** 2026-10-11

A restored agent pane now resumes its own session, never the newest one. Every known agent is
pinned to the session its own process holds, and the fallback is the agent's picker. An agent can
also report its session to its pane, and `zellij setup --agent-hooks` prints the hook that does it.
CI never cancels a run on `main` or a tag, and the release gate moved to CI. Nothing crosses a
contract; `list-agents --json` gains one optional field.

## Fixed

### A restored agent pane resumes its own session, never the newest

Two agent panes in one directory both came back holding whichever session was newest. The
recorded command used the agent's newest-session form: `claude --continue`, `codex resume --last`.

Now each pane is pinned to the session its own process holds, in that agent's own form. With no
session found, the pane comes back at the agent's picker. A newest-session flag in the argv is
never kept: `claude --continue`, `codex resume --last`, `opencode --continue` and `pi --continue`
are all recorded with the picker instead. A configured hint that adds `--continue` gets the same
treatment.

| agent | own session found from | recorded with an id | recorded with no id |
|---|---|---|---|
| `claude` | `sessions/<pid>.json` | `--resume <id>` | `--resume`, which opens the picker |
| `codex` | the `rollout-*-<uuid>.jsonl` it holds open | `resume <id>`, after argv0 | `resume`, which opens the picker |
| `opencode` | nothing | `--session <id>` | the bare command: it has no picker flag |
| `pi` | nothing | `--session <id>` | `--resume`, which opens the picker |

The sources, in order: the agent's own report on its pane (`osc`), the session file its process
holds open (`open-file`), claude's per-process record (`record`), an id already in the argv
(`argv`), and last the picker (`picker-fallback`). The walk takes the nearest process under the
pane that answers. On macOS the open files come from libproc in-process, the calls `lsof` is built
on, with no subprocess and no privacy prompt.

`list-agents --json` rows carry the answer as `session_source`: `osc`, `record`, `open-file`,
`env`, `argv` or `picker-fallback`. The field is omitted when unset. A miss is logged at `warn`
once per pane, with the pid, the agent and the reason.

## Added

### An agent reports its own session: `OSC 1337 SetUserVar=agent_session`

A hook in the agent prints `OSC 1337 SetUserVar=agent_session=<base64 id>` to its pane, the
iTerm2 and WezTerm user-variable convention. The report beats every other source. The id must be
a plain token of at most 128 characters; an empty value clears the report. A build that reads the
report lists `agent-session-osc` in `zellij setup --check --json`.

### `zellij setup --agent-hooks`

It prints the hook for each agent and the file it goes in, and writes nothing. Each hook follows
the shared agent-session contract on every session start:

1. exports `AGENT_SESSION_ID` and `AGENT_KIND` to the commands the agent runs, where the harness
   can;
2. runs `agent-sessions register` (and `unregister` at the end) when that command exists;
3. inside zellij only, prints the `OSC 1337` report.

| agent | file |
|---|---|
| `claude` | `settings.json` `SessionStart` |
| `codex` | `config.toml` `[[hooks.SessionStart]]` and `[[hooks.SessionEnd]]` |
| `opencode` (v2) | a server plugin and a CLI plugin named in `cli.json` |
| `pi` | `~/.pi/agent/extensions/agent-session.ts` |

A claude hook has no controlling terminal, so the shared script walks up to the agent process and
writes to that terminal.

### `AGENT_SESSION_ID` is read first

For every harness, `AGENT_SESSION_ID` is the first identity variable, before its native names.
When `AGENT_KIND` names another harness than the one detected, the shared id is ignored for that
pane, so a nested agent's variable never disowns its parent.

## CI and release process

- **CI never cancels a run on `main` or a tag.** `cancel-in-progress` now applies to topic branches
  only. A second push to `main` used to cancel the first commit's `Rust` and e2e runs.
- **The release gate is CI on the exact commit.** Local work runs `cargo fmt`, the format check
  and the quick loop for the area changed. The gate is a green `Rust` run on the branch push and
  green `Rust` and `End to End tests` runs on its pull request, read with `gh run list`. A local
  release build is not a gate; `release.yml` builds the artifact that ships.

## Operator notes

- **Install the hooks to get `osc`.** Without them, claude is still pinned through its record and
  codex through its rollout file. opencode and pi need a hook or a configured hint, or they come
  back at their picker.
- **A snapshot stays restorable on a rollback.** The id travels in the pane's arguments, not in a
  new layout key.
- **Nothing crosses a contract.** `session_source` is a CLI-only field. A restart picks the change
  up.
