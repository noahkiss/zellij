# v0.45.1-nkmk.28

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the one commit
  taken ahead of the next base in nkmk.22
- **Range:** `v0.45.1-nkmk.27..main`
- **Released:** 2026-10-05

What a restored session offers. After `zellij session restart`, a claude pane offered to resume
the first session it ever ran, other panes offered the starship prompt or `brew shellenv`, and one
pane offered two session choices on one line. Now an agent pane resumes the session that was live,
once, and a new top-level key decides whether anything else comes back. Nothing crosses a
contract; no `ls --json` field changes shape.

## Fixed

### A claude pane resumes the session that was live at the restart

The claude process has no `CLAUDE_CODE_SESSION_ID` in its own environment. Its children do, each
frozen at its own spawn, and the hint answered from the oldest one: an MCP server still naming the
session from before every `/clear`. The serialization pass now reads Claude Code's own record,
`sessions/<pid>.json` under `$CLAUDE_CONFIG_DIR` (else `~/.claude`), and records
`--resume <sessionId>` from it. The shipped `claude` hint is fixed with no config change. A pane
with no record keeps what the hint recorded.

### One session choice per command

A recorded `claude --dangerously-skip-permissions --continue` came back as
`... --continue --resume <id>`, and a pane restored once kept its old `--resume <id>` through
every later restart. For `claude`, `codex`, `opencode` and `pi` the recorded command now keeps
every flag except the words that pick a session, and then gets exactly one. A hint for any other
command keeps the old append-only rule.

## New

### `resurrect_commands` picks what a restored session offers

```kdl
resurrect_commands "prefill"   // or "agents", or "all" (the default)
```

| value | serialized | restored |
|---|---|---|
| `"all"`, or unset | every command, as upstream | a command pane, `Waiting to run` |
| `"agents"` | agents only, with their resume | a command pane, `Waiting to run` |
| `"prefill"` | agents only, with their resume | a plain shell with the resume pasted at its prompt, not run |

An agent is `claude`, `codex`, `opencode` or `pi`, or a command a `resurrect_command_hints` entry
names. With `"agents"` or `"prefill"`, every other pane comes back as a shell in its directory,
editors included. An agent with no hint and no live record gets its newest-session resume:
`--continue`, or `resume --last` for codex.

`"prefill"` opens the default shell and pastes the resume line once, as one bracketed paste with
no newline, the first time the shell turns bracketed paste on. That is when a line editor starts
reading a line. Enter runs it. A shell that never turns bracketed paste on gets nothing pasted.

## Operator notes

- **Add `resurrect_commands "prefill"` as a top-level line** to the shared `config.kdl` to get
  agents-only restores with the resume pasted at a prompt. It is a top-level key, so a build that
  does not know it ignores it; seeding it ahead of the binary is safe. An unknown value warns and
  means `"all"`.
- **The existing `claude` and `opencode` hints can stay.** The live record replaces the id the
  `claude` hint reads.
- **The live id is read from the server's environment.** A pane that sets its own
  `CLAUDE_CONFIG_DIR` is missed and falls back to what the hint recorded, or `--continue`.
- **Nothing crosses a contract.** One new top-level config key; no new subcommand, no
  `ls --json` change.
