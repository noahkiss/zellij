# v0.45.1-nkmk.21

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`)
- **Range:** `v0.45.1-nkmk.20..main`
- **Released:** 2026-09-14

Two patches, both on the MCP surface, and both about the same thing: what an agent asked for was
not what happened. `zellij_create` took a command string, split it on whitespace and handed the
words to a server that execs them itself, so `cd /tmp && echo "hello world" $HOME | cat` reported
`Command not found: cd`. It also took a `cwd` of `~/work` and opened the pane somewhere else
without saying so. That is the first patch. The second is placement: a created pane landed beside
whichever pane the **person** was focused on, shrinking what they were reading, in a different
place every time. An agent now gets one tab of its own, named after the tab it is in with `-zj` on
the end, and the two closes move out of `zellij_arrange` into their own tool so a client can allow
a pane to be moved without allowing a tab to be closed.

## Changed

### `zellij_create` places an agent in its own tab

```
# before - zellij_create {"command": "cargo test"}
action new-pane -- /bin/zsh -c cargo test     # beside whichever pane the PERSON is focused on
# after
action new-pane --new-tab=work-zj --no-focus --name='cargo test' -- /bin/zsh -c cargo test
```

**`kind` is now `agent_tab | pane | tab`, and `agent_tab` is the default.** That is the agent's own
tab, named after the tab the MCP server's own pane is in with **`-zj`** appended — `work` gives
`work-zj` — made on the first call and reused after. A name already ending in `-zj` is reused as it
stands, so an agent working inside one does not nest a second. A server started outside any pane
has no tab to be named after and gets `zj`. The name tells a person whose tab it is and that
closing it costs them nothing.

**It never takes the focus.** `--in-tab` places a pane without going there, and `--new-tab` would
switch the client to what it made, so the create passes `--no-focus` on both. Proved with a client
attached: the active tab and the focused pane are the same before and after, both when the agent's
tab is made and when it is reused.

**`kind: pane` is now beside the agent's own pane**, not the person's — it passes
`--near-current-pane`. `kind: tab` is unchanged.

Two consequences of `--new-tab`, both from clap. It refuses `--name`, so a pane that arrives with
its tab is named in a follow-up `rename-pane` keyed on the `pane_id:` the create printed. And it
refuses `--floating`, so `floating` with `agent_tab` is refused outright rather than working or
failing depending on whether the tab happened to exist.

**An unnamed command pane is titled with its command.** Without a `name`, the command becomes the
name, whitespace collapsed and cut to 48 characters. nkmk.20's shell wrap is why this needed
saying: the title had been reading `/bin/zsh -c cargo test`.

### `close_pane` and `close_tab` move to a new `zellij_close`

Per-verb gating is the reason this server exists — an MCP client allows or denies each tool by
name — and one `zellij_arrange` bundling four reversible moves with two irreversible closes meant a
client that wanted to allow a pane to be *moved* had to allow a tab to be *closed*.
`zellij_arrange` keeps `move_pane`, `move_tab`, `stack_panes` and `break_pane`, and is no longer
flagged destructive. The new `zellij_close` takes the two closes and is. That spends the eighth and
last tool slot, and the cap test now pins the surface shut at eight.

### `zellij_snapshot`'s `session` is renamed `of_session`

Everywhere else on this surface `session` means the session to talk to. On `zellij_snapshot` it
meant which snapshots to look at and what name to restore under, which is a different question.

## Fixed

### `zellij_create` hands its command to a shell

```
# before - {"cwd": "~/work", "command": "cd /tmp && echo \"a b\" $HOME | cat"}
action new-pane --cwd ~/work -- cd /tmp && echo "a b" $HOME | cat   # 9 argv words, no shell
  pane: Command not found: cd        # and in the session's directory, not ~/work
  tool: success

# after
action new-pane --cwd=/home/<user>/work -- /bin/zsh -c 'cd /tmp && echo "a b" $HOME | cat'
  pane: a b /home/<user>
```

**The command string was treated as argv, and reading it as one was the whole bug.** The tool split
it on whitespace and the server execs what follows `--` itself, with nothing in between, so `&&`, a
pipe, a quote and a `$VAR` all became literal arguments of the first word. It is now handed to one
shell as one word — `$SHELL -c <command>`, and `/bin/sh` when `$SHELL` is unset or empty — so
operators, quoting, globs, `~` and `$VAR` mean what they mean in a shell. Nothing in the tool parses
the command; the shell does, and it is **non-interactive**, so no rc file, alias or line-editor
rewrite gets a say.

**`cwd` promised more than it did.** `--cwd` reaches the server as a path and nothing expands it
there, so `~/x`, `$HOME/x` and a relative path were dropped without a word and the pane opened in
the session's directory — a wrong answer that looked like a right one. The tool now expands `~` and
`$VAR`/`${VAR}` against the MCP server's own environment, resolves a relative path against the
server's own directory, and passes an absolute path. One that is not a directory ends the call
before the CLI runs, naming what it resolved to.

**Success still means the pane was made**, and nothing more. What the command did is read back from
`zellij_wait_for` or `list-panes`, exactly as before.

### `close_tab` had never worked

It built `action close-tab-by-id --tab-id <n> --yes`, and that command takes a positional `<ID>` and
has no `--yes` — a clap error on every call since the tool was written. Nothing caught it because
the builder is pure and no test ran the CLI. `zellij_close`'s `tab` now names the real argument, so
the build-time check guards it like every other flag.

### A value beginning with a dash is a value

Every value-taking long flag on a create or a rename is now passed as `--flag=value`. `--name
--force` is a usage error; `--name=--force` is a name. `--name=`, `--handle=`, `--cwd=`,
`--in-tab=`, `--new-tab=` and `--pane-id=` are all built that way.

### The agent's tab is looked up, not inferred from an exit code

The create used to ask for the tab with `--in-tab` and read exit **2** as "no such tab". Clap exits
2 for a usage error as well, so a pane named `--force` was indistinguishable from the first call of
the session and made a **duplicate** `-zj` tab — nothing in the server dedupes tab names. Whether
the tab exists is now read off the `list-panes --json` answer the create was already fetching, and
the create runs once with `--in-tab=` or `--new-tab=` decided before anything runs.

### The surface map's sessions row had never matched

It was keyed on the `ls` alias while every reader looks a command up by its canonical path, so
`--dump-surface` printed no `prints:` line for `list-sessions` and `zellij_overview`'s description
said `scope=sessions` returns nothing. The row is rekeyed to `list-sessions`, and a test now
requires every `OUTPUTS` row to name a command the tree actually has.

### Descriptions that were written for a command line

**A parameter may now say what it is in the caller's terms.** Clap's help was inherited
unconditionally, and it is written for a person at a terminal: the rendered schema told an agent to
put a command "after a `--`", to pass keys "one per argument", to pass `-` to read text from a
stdin this server nulls, and that a pane defaults to "the focused pane", which does not exist here.
A non-empty `describe` now wins, and `from` goes on guarding the flag's name, so the drift
protection is kept.

The honesty fixes that came with it:

- **`zellij_wait_for` distinguishes its two exit codes.** Its own `exit_code` answers whether the
  *wait* worked; a command that failed still returns 0, and the command's status is `exit_status`
  inside the result.
- **`zellij_read_pane`** says a held pane's `[ EXIT CODE: n ]` banner is frame chrome and is not in
  the grid it returns.
- **`zellij_overview`'s `Returns:` line** named the `list-panes` columns for all three scopes while
  two of them run `list-agents` and `list-sessions`. It now names all three.
- **`zellij_write_input`** reports `action write-chars` as well as `send-keys`.
- **`zellij_close`'s tip** no longer claims a confirmation `close_tab` does not have. Only
  `close_pane` has a `--yes`; `close_tab` takes every pane in the tab with it and asks nothing.
- **`zellij_create`** no longer claims a session with no client attached cannot lay out a new tab.
  Creating is not focus-dependent, and a detached session makes a real tab.
- **Rename diagnostics** join the create's stderr on their own line, and a rename that could not be
  run keeps its error rather than losing it.

## Operator notes

- **An MCP client's tool allowlist needs updating.** `close_pane` and `close_tab` are no longer
  reachable through `zellij_arrange`. A client that allowed `zellij_arrange` for the moves now gets
  the moves and nothing else, which is the point; a client that used it to close things must allow
  `zellij_close` by name.
- **Any caller passing `session` to `zellij_snapshot` must pass `of_session`.** It is the one
  renamed parameter on the surface. Nothing else changed name, and no tool but `zellij_snapshot` is
  affected.
- **A created pane no longer appears where the person is looking**, and that is deliberate. Under
  the default `agent_tab` it lands in a `-zj` tab that does not steal focus. Set `kind: "pane"` for
  the old adjacency, now anchored to the agent's own pane rather than the person's.
- **An unnamed command pane's title and `terminal_command` name the shell.** That is nkmk.20's
  shell wrap, softened here: an unnamed pane is now titled with the command, so the shell shows only
  in `terminal_command`. The consumer repo makes no command panes and reads neither field.
- **Nothing crosses a contract.** CLI-side only: `src/mcp/` and one row of
  `zellij-utils/src/cli_surface.rs`. No protobuf, no client/server contract change, and no CLI flag
  added — every flag this uses (`--in-tab`, `--new-tab`, `--no-focus`, `--near-current-pane`) had
  already shipped. `zellij action new-pane` itself is untouched, so `list-panes --json` keeps its
  shape and no config key changed meaning.
