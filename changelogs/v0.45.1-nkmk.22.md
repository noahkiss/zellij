# v0.45.1-nkmk.22

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus one commit taken
  ahead of the next base (below)
- **Range:** `v0.45.1-nkmk.21..main`
- **Released:** 2026-09-28

One fix and one upstream cherry-pick, and neither changes a flag, a field name or a contract. The
fix is to a number that was already there: `last_output_at` on `list-panes --json` moved by a
millisecond between two reads of an idle pane, so a consumer diffing the pane list saw every pane
as busy on every tick. The cherry-pick is upstream's: the bundled plugins are no longer copied
onto the heap at start, and the server's resident size falls by roughly the size of the bundle.

## Fixed

### `last_output_at` is the same number on every read of an idle pane

```
# before - two list-panes --json reads of a pane that wrote nothing in between
"last_output_at": 1790615664836
"last_output_at": 1790615664835
# after
"last_output_at": 1790615664836
"last_output_at": 1790615664836
```

**The stamp was rebuilt on every read.** The server kept the moment a pane last wrote as an
`Instant`, and each `list-panes` turned it into a wall-clock millisecond as *now* minus *how long
ago*, with the two clocks truncated to the millisecond on their own. Their fractional parts drift
between reads, so an idle pane's stamp wobbled by 1 ms and a consumer that compares two reads —
that is the field's whole purpose — took the wobble for output.

The server now takes the wall-clock millisecond once, when the pty bytes arrive, stores it beside
the `Instant` the mobile view still uses, and reports the stored value verbatim. A unit test reads
an idle pane forty times over sub-millisecond gaps and requires one value. Proved on a live
session: three reads 1.5 s apart returned one number where nkmk.21 returned two.

## Changed

### The bundled plugins stop being copied onto the heap

Upstream `f19b2ce82`, taken as a `chore(upstream)` commit that drops out at the next rebase.
`ASSET_MAP` holds a `&'static [u8]` into the binary instead of a `Vec<u8>` copy of each plugin, so
the ~17 MiB of embedded wasm is no longer duplicated at start. Measured on the release candidate: a
fresh server at rest was 60–75 MB resident against 117–119 MB for nkmk.21 on the same machine.
Nothing observable changes but the number.

## Operator notes

- **A consumer that tolerated the wobble can stop.** Anything that held `last_output_at` through a
  few milliseconds of jitter to keep an idle pane idle can compare for equality once every host it
  reads runs this build.
- **Nothing crosses a contract.** `PaneInfo` keeps its fields; only the value's stability changed.
  No protobuf, no client/server contract, no CLI flag, no config key. The plugin API is untouched:
  `ASSET_MAP` is a server-side table.
- **The upstream pick is named in `FORK.md`'s opening**, beside the base, so the base stays a
  named tag plus a named commit and not "main plus whatever".
