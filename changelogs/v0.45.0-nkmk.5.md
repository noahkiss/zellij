# v0.45.0-nkmk.5

- **Upstream base:** `f42ca3c79` on upstream `main` (workspace version `0.45.0`) — unchanged since
  nkmk.1
- **Range:** `750d8c7a3..main` (56 commits)
- **Released:** 2026-08-13

Two halves. The first builds a harness bridge: background plugins get pane and tab updates with no
client attached, `PaneInfo` gains pid, cwd, command, last-output time, pending-bell state and an
opt-in per-pane environment allowlist, new events announce a pane opening or exiting and a plugin
dying, and a batch of CLI surfaces exposes what plugins already had. The second is a correctness
pass: CLI actions now fail loudly instead of exiting 0 on a miss, `web_request` stops hanging on a
dead endpoint, session metadata stops dropping pane identity, and a slow subscriber stops getting
silently dropped.

## Added

### Background plugins get pane and tab updates without a client

A background plugin subscribed to `PaneUpdate` or `TabUpdate` only heard from the session while the
right client happened to be attached. Both dispatch functions built their target list from the
connected clients, and detaching a client emptied that list — so a fully detached session delivered
neither event to a harness watching it. Attached was not safe either: delivery rode on whichever
client currently held the low id the plugin loaded under, so two clients could leave the plugin
silent with one plainly attached.

Both dispatches now read subscriptions directly, once per state change, independent of who is
connected. A plugin loaded into a visible pane is excluded from this path — it already gets updates
as an active-tab plugin, so it is never served twice, even if it later moves tabs. A dead
background plugin's subscription is dropped on unload or crash, so Screen stops building it a
manifest forever.

### `PaneInfo` gains pid, cwd and command

```
zellij action list-panes --all --json
```

Terminal panes carry `pane_pid` (the pane's own shell, not what it runs), `pane_cwd` and
`pane_command` (the foreground command, or the shell if none). These were CLI-only before this
release, resolved with a blocking per-pane round trip to the pty thread. The pty thread already
refreshes a warm cache once a second, and now stamps it onto every `PaneInfo` — plugins, peer
sessions and the CLI read the same numbers, and the CLI's blocking probes are gone.
`Event::CwdChanged` / `Event::CommandChanged` remain the push half; these fields answer what a
consumer needs at the moment it starts watching. Proto tags 32-34.

### `last_output_at` and `has_pending_bell`

`PaneInfo.last_output_at` is the time a pane last emitted bytes — a liveness signal costing one
clock read, no content scrape. It moves on the once-a-second tick, not the instant bytes land. A
related fix on the same path: a shell emitting OSC 7 used to clear the pane's activity flag, which
starved `pane_command` refreshes for any shell announcing its cwd at every prompt; the flag now
stays set. Proto tag 35.

`PaneInfo.has_pending_bell` is `true` for a pane that rang while unfocused and unseen since. Bell
processing used to sit inside the client-render branch, so a fully detached session recorded no
bells at all. The sweep now runs before that gate; only the flash and the forwarded ANSI BEL still
need a client. Always `false` when `visual_bell` is off. Proto tag 36.

### `report_pane_env`: an opt-in environment allowlist per pane

```kdl
report_pane_env "CLAUDE_CODE_SESSION_ID" "MY_TOOL_ID"
```

`PaneInfo.pane_env` reports named variables found in the pane's own process or its descendants,
nearest first — the same walk `resurrect_command_hints` uses. It answers which instance of a tool a
pane is running, without a consumer reading `/proc` itself. It is an allowlist and only an
allowlist: unset reports nothing, no defaults, exact names, no patterns.

Cost is zero with the list unset. With it set, the walk stops early only once every named variable
is found — a name that is absent costs a full subtree read every second for the pane's life, and on
macOS each such read allocates a roughly 1MB buffer. Keep the list short. Does not round-trip
through `session-metadata.kdl`: a peer session reports an empty `pane_env`, since writing named
environment values to a file every session on the box can read is a different exposure than the
event path. Proto tag 37.

### Eight more fields a pane already knew about itself

`is_alternate_screen`, `scrollback_position`, `scrollback_length`, `is_pinned`, `logical_position`,
`is_borderless`, `exclude_from_sync` and `has_explicit_title` move from server-internal trait
methods onto `PaneInfo`, reaching the CLI, plugins and peer sessions on the same path.
`frame_color_override` was skipped: it is a one-second flash cleared by a background job, so a
once-a-second manifest would sample it at random. `session-metadata.kdl` carries six of the eight —
not the two scrollback fields, which describe a viewport a peer reader cannot act on. Proto tags
38-45.

### `Event::PaneOpened`, `Event::PaneExited`, `Event::PluginDied`

`PaneClosed` was the only structural lifecycle event; removal was already observable detached,
creation was not — a consumer had to diff manifests. `Event::PaneOpened(PaneId)` closes that gap,
firing from every creation path once the pane is placed, but not for a pane that only moved between
tiled, floating or another tab.

`Event::PaneExited(PaneId, Option<i32>)` reports a command pane's exit status to every subscriber,
not just the plugin that opened it — before this, a pane started by a layout or `new-pane -- <cmd>`
had no plugin to report to, so a build failing in a background tab told nobody. `None` means killed
by signal or unreadable, not success.

`Event::PluginDied(plugin_id, message)` tells every subscriber when a plugin crashes. A background
plugin has no pane to show a loading error in, so a crash used to be one `log::error!` and silence.
Nothing restarts the plugin; this is a signal, not a policy. Each plugin id is announced once, so
two plugins dying on `PluginDied` cannot loop each other.

### `zellij setup --check --json`: a machine-readable capability document

```
zellij setup --check --json | jq -e '.capabilities | index("pane-uuid")'
```

Reports capability names, a `base_version`/`fork_counter` pair, feature flags and directories as
JSON. Gate on capability names, not the version string — the fork counter resets on an upstream
bump, so `0.45.0-nkmk.4` is newer than `0.44.3-nkmk.7` while `4 < 7`, and a counter comparison
switches features off on an upgrade, silently.

**It reports `"scope": "binary"` — it describes the installed binary, not a running server.** During
the fork's normal upgrade window, a new binary is installed while old sessions keep running the
server they started with, and the binary can claim capabilities those sessions do not have. A
consumer gating per session must treat the list as an upper bound until that session restarts, and
fall back when a promised call is refused. This release also fixed the document to build itself key
by key, so an upstream build omits `fork`/`fork_counter` entirely instead of emitting them null.

### CLI surfaces for what plugins already had

- **`ls --json`** / **`list-clients --json`** — array output instead of fixed-width columns. `ls
  --json` adds `connected_clients`, `web_client_count`, `tab_count`, `pane_count` from each
  session's `session-metadata.kdl`.
- **`break-pane`, `break-pane-to-tab`, `break-pane-right`, `break-pane-left`** — move panes between
  tabs. A pane id naming nothing is now an error, not a silent skip that could leave an empty tab
  behind — this also applies to the plugin calls sharing the same instructions.
- **`signal-pane`** — send SIGINT, SIGHUP or SIGKILL to a pane's process. `--pane-id` is required, so
  a destructive call never falls back to whatever is focused.
- **`move-pane-between-tabs`** and **idempotent setters** for fullscreen, pinned, float and tab sync
  — exit 0 on a real change, 2 when already so, so a controller can converge without reading first.
- **`go-to-tab-name --no-focus`** — create or confirm a tab without stealing focus. Without
  `--create`, stdout carries the answer and the exit code stays 0 either way; a script tests output,
  not `$?`.

### Two bars ship in the binary (`builtin_plugin_dir` for developing them)

`slim-tab-bar` and `slim-keybinds` move from external `file:` plugins into the binary — no `.wasm`
to track in dotfiles, no version to keep in step with the binary loading them. Neither calls
`request_permission` any more: a builtin's checks already short-circuit to `Granted`, so a request
only ever raised a prompt nobody could answer. `builtin_plugin_dir "<path>"` keeps bundling from
costing hot-reload: when a file for a builtin's name exists there, the server loads it instead of
the embedded copy, and `plugin_watch` watches it. Config-file only; production runs the embedded
copy.

## Fixed

### CLI actions exit non-zero on a missing pane or a timeout

Several `zellij action` commands exited 0 and printed nothing when the named pane did not exist:
`write`, `write-chars`, `paste`, `close-pane` (on the path the interactive CLI actually sends, which
a first fix missed), `edit-scrollback`, and `break-pane-to-tab-with-index` via a stale plugin pane
id. Each now sets the same exit status and "Pane with id ... not found" message the rest of the
by-id family already used.

Separately, the wait for an action's result was capped at one second, so legitimately slow work — a
heavy layout, a session's first plugin load compiling wasm — reported failure while the action went
on to succeed. The budget is now five seconds, and a timeout says the action may still complete
rather than claiming it failed. Both land under one capability name, `cli-error-reporting`.

### `web_request` times out, and a dead endpoint answers instead of hanging

The HTTP client had a literal `TODO: timeout?` — an endpoint that accepted a connection and never
answered held the plugin's request, and its correlation entry, forever. It now gives up after 30
seconds, 10 of which the connect phase may use. Every transport failure was also synthesized into a
fake HTTP 400, so "connection refused" and "the server rejected this" were distinguishable only by
string-matching the body; a request with no HTTP response now reports status 0 with an
`x-zellij-error-kind` header naming the failure. A session whose HTTP client failed to build at
startup used to hang every `web_request` it would ever make; that path answers the same way now.
Capability name: `web-request-timeout`.

### A slow subscriber is no longer silently unsubscribed

A full client buffer was read as a dead client: the subscription was dropped with no `Exit`, no
`SubscribedPaneClosed`, and no log line — leaving a live socket that would never emit again. Busy
and gone are now distinguished; a busy subscriber keeps its subscription and its viewport, so the
next tick re-sends what it missed, and only a departed client loses one.

Companion fix in the route thread: a disconnected peer and a message that failed to decode used to
return the same signal, driving a dead peer through 1000 tight iterations and two misleading log
lines before cleanup. A disconnect now ends the loop immediately, with a line naming what happened.

### Smaller server and pane fixes

- `session-metadata.kdl`, how a plugin sees a peer session, dropped 22 of `PaneInfo`'s 31 fields —
  `uuid`, `restored_from`, `program_title`, the stack fields and more. All now round-trip.
- A poisoned crash-announcement lock read as "already announced", silencing every future crash for
  the session's life — and a dead background plugin has no other symptom. It now fails open.
- A held pane (`hold_on_close`) kept the pid of its reaped child, so `signal-pane` could hit an
  unrelated process once the OS reused that pid. The reaping thread now clears it.
- The once-a-second pid/cwd/command map was resent to Screen even when unchanged, waking the screen
  thread forever in an idle session. Now skipped when equal to the last one sent.
- A busy pane-render send that refused mid-batch skipped retained-viewport bookkeeping for the whole
  batch, not just the refused pane. Skip is now keyed by (subscriber, pane).
- A shell with job control off (`setopt no_monitor`, `set +m`) never recorded a running command,
  since process-group discovery can't tell idle from busy without it. Checked by child process now,
  like the Windows arm already was.
- A restored session came back with tabs in creation order, not the order left in — the layout
  writer and `query-tab-names` both iterated a map keyed by tab id instead of sorting by position.
- Moving, renaming, adding or closing a tab briefly redrew every *other* tab's bar with the old list
  on arrival. Updates now reach every tab's plugins only when the list changed, active tab's
  otherwise — switching stays as cheap as upstream.
- `PaneFrameStyle::TopOnly` did not reach floating panes, whose render path never called the
  function that applies it.
- The session listing broke a same-second age tie by hash order. Ties now break on name.

## Changed

### macOS Full Disk Access survives an upgrade

A package manager installs into a versioned directory, so the running binary's path — the only one
the about page (`Ctrl+o` `a`) showed before — is gone at the next upgrade, taking its Full Disk
Access grant with it. A second line now names the stable path when it differs, and `<c>` copies it.
`pin_exe` now redirects the **server** to that stable copy for a session started by hand, not only
the generated service unit — previously only the launcher-started path avoided the versioned
directory, so Full Disk Access was re-granted after every upgrade for most sessions.

### Notices the server draws over the viewport

Full Disk Access not granted, and this session running a superseded build, are now drawn by the
server itself, top-right, composited after pane rendering so no application can clobber them and
`dump-screen` never sees them. Re-checked every 30 seconds.

## Upstream

`git fetch upstream` reports no commits past `f42ca3c79`. The base is unchanged since nkmk.1.

**The plugin API changed**: `event.proto` gained new event types (`PaneOpened`, `PaneExited`,
`PluginDied`) and new `PaneInfo` fields (pid, cwd, command, `last_output_at`, `has_pending_bell`,
`pane_env`, and the eight trait-derived fields). All additions are new tags on existing messages, so
a plugin built against nkmk.4 keeps working — it decodes the new fields and event variants as
unknown and ignores them. Rebuild against this release's `zellij-tile` to read them. The bundled
plugins, including the two builtin bars, are rebuilt for this release.
