# v0.45.0-nkmk.13

- **Upstream base:** `98a083707` on upstream `main` (workspace version `0.45.0`) — moved up from
  `f42ca3c79`, which had been the base since nkmk.1
- **Range:** `98a083707..main` (35 commits — the whole patch series, replayed onto the new base)
- **Released:** 2026-08-16

This release is two destructive bugs and a new upstream base.

Both bugs had been reported as something else. A stacked pane that came back corrupted, and was
repaired by scrolling, was a collapsed member whose grid had been squashed to one row. A session
that vanished after `attach -c`, leaving its processes alive and unreachable, was a create that
bound over a live server's socket. Neither is a rare path: the first fires whenever a stack member
is collapsed, and the second cost a real session with 10 tabs and 41 panes on the day it was found.

The base also moves for the first time since nkmk.1, and it brings six upstream commits.

## Fixed

### A collapsed stack member keeps its grid, not only its pty

A pane in a collapsed stack could come back full of characters from two different redraws.
Scrolling up and back down appeared to repair it. The bug had been there since nkmk.5.

nkmk.5 stopped the layout pass from resizing a collapsed member's **pty**, so the shell in it would
not reprint. That was half the patch. The **grid** is resized by a different route: every
`set_content_offset` and every `set_geom` calls `reflow_lines`, which resizes the grid to whatever
the geometry and the offset imply. A collapsed member is handed two offsets in one pass, and the
first of them squashed its grid to a single row.

So the program in the pane was told it still had N rows, kept drawing N rows, and drew them into a
grid one row tall. Every absolute cursor move past row 1 scrolled instead of overwriting, and each
redraw was shredded into the scrollback. Re-expanding grew the grid back holding the tail of one
frame above the head of the next. Scrolling seemed to fix it because it pulled the whole rows back
out of the scrollback.

The fix states the invariant at `reflow_lines`, which is the single point all of those routes pass
through: a collapsed stack member's grid is frozen, by the same `is_collapsed_stack_member`
predicate that already frees its pty. Guarding the layout pass instead would have covered the
offsets and left `set_geom` to squash the grid on its own, because it reflows at the moment the
geometry becomes one row.

One integration snapshot moved with the fix, and its direction is the proof: a collapsed member no
longer wears a `[ SCROLL: 0/1 ]` badge, because it no longer has a line pushed into its scrollback.

### Creating a session never takes a live server's socket

`zellij attach --create` on a session that was already running created a **second** session on top
of it. The first survived only as a process nobody could reach.

The cause is a liveness probe that answers the wrong question for a destructive decision.
`session_exists` connects to the socket, sends `ConnStatus` and waits for `Connected`. A server that
accepts the connection but does not complete that exchange is reported as absent. For a listing that
is defensible. For `--create` it is fatal: the create that follows binds the same path, and the bind
is preceded by an unconditional `remove_file`. The old server keeps running and keeps its listening
socket, but a unix socket cannot be given its pathname back. The session is gone while every one of
its processes is still alive.

The fork now asks a smaller question before any create: **is anything bound**. A bare `connect()`
that succeeds means a live process is listening, whatever it goes on to say, and that is enough to
refuse. That guard sits in three places — `attach --create` and its resurrect and restore branches,
the plain `zellij --session <name>` create, and `start_server` itself, which is the one a client
cannot race or bypass.

A stale socket left behind by a dead server is still cleaned up and replaced, because `connect()` to
it fails. Only a socket with something alive behind it is protected. The refusal names the socket,
says why the session is missing from `zellij ls`, and points at `zellij attach` to reach it or
`zellij session restart` to replace it deliberately.

## Changed

### The upstream base moves to `98a083707`

The base had been `f42ca3c79` since nkmk.1. It is now `98a083707`, and the move brings six upstream
commits:

| Commit | What it changes |
|---|---|
| `98a083707` | reading the terminal's paste buffer becomes opt-in, off by default |
| `a9db5664b` | a `copy_command` process is no longer killed while it still owns the selection |
| `c428ae93b` | scroll position survives leaving scroll mode |
| `6343be42c` | scrollback is no longer truncated when a pane joins a stack in list mode |
| `30c9d2fcb` | the missing `NestedListItem` colour helpers arrive in the plugin API |
| `dc6d8209e` | a spelling fix in the session name list |

Three of them met a patch here. Upstream's paste-buffer option and this fork's
`default_floating_size` both extend the `Reconfigure` instruction, so both fields are carried.
Upstream added a private `pane_exists` to `Screen` whose body is identical to the one the CLI
patches already made public, so the private copy is dropped. And upstream's new scroll-mode test
snapshot is re-recorded, because a pane frame here also carries the pane's two-word handle.

`6343be42c` is worth noting beside the stack fix above. Upstream fixed scrollback being truncated
when a pane **joins** a stack; the fork fixed a collapsed member's grid being squashed while it
**sits** in one. They are different bugs in the same area, and both are in this release.

### The patch series is regrouped, and releases go through a release candidate

Main's history was rewritten into about 30 logical commits — one per ledger entry, grouped by
subject rather than by the order the work happened in. That keeps the series readable when it is
replayed onto a newer upstream tag, which is how this fork moves.

The cost is that the regrouped series does not bisect. A file lands with its group, so a definition
can sit in a commit placed after one of its callers, and an intermediate commit may not compile. The
tip and the last commit of each release do. The last chronological, bisectable history is kept at
`backup/main-pre-squash-2026-08-16`.

Every release is now proved as a release candidate first. An RC tag — `v0.45.0-nkmk.13-rc.1` —
builds and publishes exactly like a final tag, with two differences: the GitHub release is marked as
a prerelease, and the tap bump rewrites a separate `zellij-nkmk-rc` formula. So a candidate can be
installed on a real machine while everything else keeps running the last final release:

```
brew update && brew unlink zellij-nkmk
brew install noahkiss/tap/zellij-nkmk-rc
# ... prove the patch ...
brew uninstall zellij-nkmk-rc && brew link zellij-nkmk
```

The binary reports no `-rc.N`. The suffix lives on the tag only, so `zellij --version` prints
`0.45.0-nkmk.13` under a `v0.45.0-nkmk.13-rc.1` tag, and the tap strips the suffix before comparing.

## Upgrading

Nothing is required. No config key is added or removed.

One older key is worth re-checking while you are here. In `resurrect_command_hints`, **`resume_args`
holds arguments to append**, not a command line. The retired `rewrite` key held a whole command, and
the two are easy to confuse, because the migration changes the *value* as well as the key name:

| block | the retired `rewrite` | the correct `resume_args` |
|---|---|---|
| `claude` | `rewrite "claude --resume {}"` | `resume_args "--continue"` |
| `opencode` | `rewrite "opencode --session {}"` | `resume_args "--session {}"` |

A config that keeps the old value under the new key appends a second command name to the observed
command line. The command itself always comes from the pane; the hint only adds to it.
