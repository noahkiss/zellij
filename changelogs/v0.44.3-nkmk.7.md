# v0.44.3-nkmk.7

- **Released:** 2026-08-05

*Back-written 2026-08-10 from the git history and FORK.md.*

A launcher's environment is not the calling shell's, and this release works through what that
breaks. It also stops the job lookup from trusting the name the job was installed under.

- A session created by a launcher gets a usable `TERM`, and a pane's shell comes from the passwd
  entry when nothing exported `SHELL`.
  See [A session created by a launcher gets a usable `TERM`](../FORK.md#a-session-created-by-a-launcher-gets-a-usable-term)
  and [A pane's shell comes from the passwd entry](../FORK.md#a-panes-shell-comes-from-the-passwd-entry-when-nothing-exported-shell).
- `up` builds the environment a created session hands out: `COLORTERM` and the `ZELLIJ_*`
  variables, on the same path.
  See [`COLORTERM`, and the `ZELLIJ_*` variables](../FORK.md#colorterm-and-the-zellij_-variables-on-the-same-creating-path).
- `enable`, `disable` and `status` find the installed job by what it runs, not by what it is
  called — including a job written by hand or by an older build. `disable` exits non-zero while
  another launcher still runs the session.
  See [The installed job is found by what it runs](../FORK.md#the-installed-job-is-found-by-what-it-runs-not-by-what-it-is-called)
  and [`zellij session enable|disable|status`](../FORK.md#zellij-session-enabledisablestatus).
- The generated units say where output goes, and give the server a `PATH`.
  See [`zellij setup --generate-service`](../FORK.md#zellij-setup---generate-service-systemdlaunchd).
- The unit guard refuses a directive that assigns, not one that merely mentions.
  See [Extra unit directives from the config](../FORK.md#extra-unit-directives-from-the-config-session_service).
- Build: an iteration profile, so development no longer loops on `--release`.
