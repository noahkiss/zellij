# v0.45.0-nkmk.9

- **Upstream base:** `f42ca3c79` on upstream `main` (workspace version `0.45.0`) — unchanged since
  nkmk.1
- **Range:** `v0.45.0-nkmk.8..main` (1 commit)
- **Released:** 2026-08-15

One fix, and it is the other half of the signing story. **nkmk.8 was proven good on a Mac that
already holds an Apple certificate and hung forever on one that does not.** The machine with the
certificate signed and verified from the release artifact exactly as nkmk.8 said it would. The
machine without one fell to the rung that mints its own certificate, and stopped there — no
timeout, no dialog, an empty report, and `zellij session doctor --fix` never returning. nkmk.9 makes
that hang impossible, and makes the step it hung on unable to end a run at all.

## Fixed

### Nothing doctor runs can stop at a password prompt

`security set-key-partition-list` was waiting for input. It writes its prompt to the **controlling
terminal** — not through the window server, and not to stdin — so on the minted rung it appeared as
one line on the pane's own terminal and nowhere else:

```text
(deprecated) password to unlock /Users/…/login.keychain-db:
```

There was no SecurityAgent process and no dialog. The comment on that call had assumed one would
appear, which is why being inside a graphical session was treated as sufficient. It is not.

**Every child doctor runs is now started with `setsid(2)`**, in a session of its own with no
controlling terminal to open. A tool that would have prompted fails fast and says why. The null
stdin that was already set is not the fix and never was — `security(1)` opens `/dev/tty` and does
not read the password from stdin. Doctor runs from launchd, from a detached pane and over SSH, and
none of those can answer a prompt; a doctor that hangs is worse than every failure it exists to
report.

**`set-key-partition-list` can no longer end the run.** That is the half that turned a stall into a
machine with nothing signed. The call is a convenience: it decides whether macOS asks for the key
once per signature or never. `codesign` raises that dialog itself, and a person at the desktop
answers it once with **Always Allow**. So a refusal is now reported as `Needs you` and the run goes
on to sign. If `codesign` then refuses too, the report names **both** remedies on every exhausted
ladder — run doctor from a terminal in the desktop session and click Always Allow, or set
`ZELLIJ_KEYCHAIN_PASSWORD`. The minted rung is included, and it is the one that needs it most: its
key is precisely the one no person has ever approved.

**`ZELLIJ_KEYCHAIN_PASSWORD` is not an SSH-only escape hatch**, and three places said it was. The
prompt goes to the controlling terminal wherever the run happens, so a pane and a launchd job stall
exactly as an SSH session does. It is read from the environment when it is set, and doctor asks for
it — or for anything else — never.

A machine whose certificate import succeeded before the hang does not mint a second certificate on
the next run. The untrusted listing added in nkmk.8 finds the certificate already in the keychain,
and the ladder signs with it.

## Upstream
