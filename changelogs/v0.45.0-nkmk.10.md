# v0.45.0-nkmk.10

- **Upstream base:** `f42ca3c79` on upstream `main` (workspace version `0.45.0`) — unchanged since
  nkmk.1
- **Range:** `v0.45.0-nkmk.9..main` (1 commit)
- **Released:** 2026-08-15

**nkmk.9 shipped half of this work and should be skipped.** The keychain fix was two commits; only
the first was on the tag when it was cut, an hour before the second landed. nkmk.9 is a real
improvement on nkmk.8 and does no harm, but it does not finish a Mac. This release adds the other
commit, and it is the one that makes the minted rung actually sign.

The proof for both came from finishing an m1p-class Mac — one holding no Apple certificate — by
hand. The minted rung now imports and signs. Getting there hit two walls in sequence: the run hung
on a terminal password prompt (fixed in nkmk.9, carried here), and every run **after** the one that
minted was then refused by a key ACL that had only ever been granted at minting time. That second
wall is what nkmk.10 removes, along with the reason nobody could see it.

## Fixed

### Grant the key ACL on every run, and quote the real refusal

**The key ACL was granted only on the run that minted.** `security set-key-partition-list` ran from
`ensure_self_signed`, which a machine reaches once in its life. Every run after that found the
certificate as a ready rung, signed with it, and was refused by a key nothing had ever approved.

The two lifetimes were never the same one, which is the whole bug: the ACL belongs to the
**keychain**, and the certificate is minted once and then signed with for years. So the grant now
runs before **every** signature made with our own certificate. It is cheap, and idempotent when the
ACL is already there. Proven on a real Mac — running the partition list by hand made the identical
`codesign` succeed.

It stays off the Apple rungs. Those certificates arrive with their own ACL, and rewriting the
partition list of a key doctor did not create is not doctor's business.

**And the refusal that would have said so was hidden.** `-f` makes `codesign` announce

```text
<path>: replacing existing signature
```

before anything else, on every run after the first. The report quoted its **first** line — so a
real failure was reported as the one thing that had gone right, with the actual
`errSecInternalComponent` sitting on line 2 and appearing nowhere in the output. That is why this
fault survived a release: the report described a success.

The informational line is now dropped and everything else is kept, joined and capped. Kept rather
than reduced to the last line, because `codesign` can emit several and the one explaining a refusal
is not reliably the last one either.
