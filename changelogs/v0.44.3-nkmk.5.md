Session lifecycle becomes a command, and an init system can hold it up. `zellij session up` creates
a session and then asserts its own post-condition; `setup --generate-service` writes the unit that
calls it.

- `zellij session up|down|restart`, with post-conditions. `up` is idempotent, and `down` is too.
  See [Session lifecycle](../FORK.md#session-lifecycle-zellij-session-updownrestart).
- `zellij setup --generate-service <systemd|launchd>` generates a user-level systemd unit or
  launchd plist. The generated files name a stable binary path, load the agent into the graphical
  login session, and do not throttle the session.
  See [`zellij setup --generate-service`](../FORK.md#zellij-setup---generate-service-systemdlaunchd).
- `session up` refuses to create a session in the wrong macOS session domain.
  See [`session up` will not create a session in the wrong macOS session domain](../FORK.md#session-up-will-not-create-a-session-in-the-wrong-macos-session-domain).
- Configured env vars are dropped when this binary creates a session, so a tool's marks do not leak
  into every pane.
  See [Environment variables dropped when a session is created](../FORK.md#environment-variables-dropped-when-a-session-is-created).
- Configurable terminal title, with session name aliases.
  See [Configurable terminal title](../FORK.md#configurable-terminal-title).
- `~` and `$VAR` expand in config paths, as they already did in layouts.
  See [`~` and `$VAR` in config paths](../FORK.md#and-var-in-config-paths).
- Test: a denied plugin permission leaves no cache entry, not an empty one.
  See [Declarative plugin permissions](../FORK.md#declarative-plugin-permissions).
