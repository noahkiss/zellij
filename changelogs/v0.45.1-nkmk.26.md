# v0.45.1-nkmk.26

- **Upstream base:** unchanged — the `v0.45.1` release tag (`efd8fd5a8`), plus the one commit
  taken ahead of the next base in nkmk.22
- **Range:** `v0.45.1-nkmk.25..main`
- **Released:** 2026-10-02

Two fixes. On a Mac with a loaded launch agent, `session restart --fresh` never came back fresh.
And the MCP server taught key spellings and handles that the CLI then refused. Nothing crosses a
contract; no `ls --json` field changes shape.

## Fixed

### `session restart --fresh` comes back fresh when a launch agent creates the session

```
$ zellij session restart --fresh mysession
# before, on a Mac with the session's launch agent loaded: exit 0, and every tab from
# before the restart was back
# after
ok    'mysession' came back fresh from the layout
```

With a launch agent loaded, or a managed session's unit known, the restart's inner `up` does not
create the session. It releases the lock and asks launchd or systemd to. The job it wakes runs a
bare `session up`, and a bare `up` resumes. So `restart --fresh` came back from the snapshot its
own teardown had just archived, and `restart.log` reported success. On a Mac with an agent this
happened every time, not by race.

`restart` now writes the shape it wants to `<socket-dir>/.<name>.up.pending`, before the teardown
and again after it. The `up` that creates the session takes the file and builds that shape. An
explicit `--fresh` or `--restore` on that `up` still wins. A file older than two minutes belongs to
a restart that died, and is removed and ignored. After its `up`, `restart` checks the file once
more. If nothing took it — an older build created the session, or the session was already up —
`restart` removes it, says the session did not come back as asked, and exits 1.

### The MCP server's key and handle docs say what the CLI accepts

`zellij_write_input` taught `C-c` and `Escape`, and the key parser refuses both. It now names
`Ctrl c` and `Esc`, says `C-c` and `Ctrl-c` are not keys, and says `keys` takes one key per call.
A test parses every key the tool's text offers.

`--handle` help said only "lowercase words joined by dashes", so `plugin-check` looked valid and
the CLI refused it as too close to a pane id. The help on all five `--handle` flags now states the
whole rule, and so does `zellij_create`'s `handle` description. `zellij_create` checks a handle with the CLI's own rule before it runs anything:

```
zellij_create {"kind": "pane", "handle": "plugin-check"}
# before: a process spawned, and the CLI refused the flag
# after: refused at once, with the CLI's reason — too close to the pane id
```

## Operator notes

- **A restart honours `--fresh` only when the build that creates the session is nkmk.26 or
  later.** The launch agent runs the pin, so upgrade and re-pin before relying on it. A restart
  whose request nobody took now exits 1 and says so, instead of reporting success.
- **Nothing crosses a contract.** No new config key, no new subcommand, no `ls --json` change.
