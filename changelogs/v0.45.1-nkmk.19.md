# v0.45.1-nkmk.19

- **Upstream base:** the `v0.45.1` release tag (`efd8fd5a8`) — moved from the `v0.45.0` tag
  (`13e1c25a2`), nineteen upstream commits away
- **Range:** `v0.45.0-nkmk.18..main`
- **Released:** 2026-09-09

A patch-release rebase, and two papercuts that only ever bit the person at the keyboard. The base
moves to upstream's `v0.45.1` — nineteen commits of fixes, one of which stops an idle server
burning a core — and all 118 fork patches replayed onto it, with none dropped and none added. On
top of that: a command pane a session restore brought back no longer waits for the keypress it was
always going to get, and `session doctor` stops telling a Mac without Full Disk Access that its
server may be wedged.

## Changed

### The base is the `v0.45.1` release tag

The series was rebased from the `v0.45.0` tag onto `v0.45.1`, a nineteen-commit patch release.
Nothing dropped out as upstream-absorbed and nothing was added; twenty-two patches took textual
drift, and the two upstream-facing snapshot suites were re-checked on the new base.

What the base move brings a user:

- A CLI pipe is released when the plugin handling it crashes, instead of leaving the caller waiting.
- Floating plugin panes are told when their tab goes away — including on the last-client-disconnect
  path — so a session picker left open no longer polls the full session list forever. An idle
  server with no attached client stops spinning.
- Nested-session detection no longer needs the environment variable read through a nested shell, so
  it is right over SSH.
- The OSC 99 notification handling introduced in 0.45 is fixed.
- Kitty images: reported pixel dimensions reach ptys that already exist, and the images of
  collapsed stack members are cleared.
- Scroll-mode sync can be opted out of.
- A theme hue can be set explicitly instead of guessed.
- A session can be started with an initial command.
- The floating editor works fullscreen.
- Focus events from outside are handled in the web client.
- The first-run wizard unlocks the first nested session's keybindings.
- A layout composes the containing node's cwd into its floating panes.
- A fixed-size layout pane keeps room for its title.

**No fork option changed name, value, default or effect.** Every config key, flag and default this
fork adds behaves exactly as it did in nkmk.18.

### A resurrected command pane drops to the shell when its command exits cleanly

A pane brought back by a session resurrection used to end its command the way every command pane
does: hold, print `EXIT CODE: 0`, and offer `<ENTER> run, <ESC> drop to shell, <Ctrl-c> exit`. For
a tool you quit on purpose — a coding agent, a REPL — the answer was always ESC, so the banner was
a keypress standing between finishing and having a prompt back. The pane now takes the ESC path
itself, landing at a shell in the directory the command ran in.

It is the ESC path, not a copy of it: the same trait method, the same `DropToShellInPane`, the same
default shell, the pane still held first and released a moment later.

Scope is exactly panes whose command came back with a session, decided by the layout file name
(`session-layout.kdl`, which is what both resurrection sources write). **A failure still holds** —
only `Some(0)` takes this path, so a non-zero status prints its code as before and a killed child,
which reports `None`, does too. **A layout command pane is untouched**, hold and ENTER-to-re-run
included. There is no config key.

Nothing crosses a contract: the `resurrected` flag is `#[serde(skip)]`, is in neither protobuf, and
is kept out of `RunCommand`'s `PartialEq`.

## Fixed

### A slow Full Disk Access denial is not a wedged server

```
$ zellij session doctor mysession        # before, on a healthy Mac without the grant
Needs you
  probe     the pane probe did not answer in time
            the pane was opened, so the server may be wedged
```

Nothing was wedged. The macOS probe opens a floating pane that writes two lines: `manager=` the
moment the pane's shell starts, and `fda=` after an `open(2)` on `TCC.db`. TCC is fast to allow and
slow to refuse — measured at about 5.5 to 5.8 seconds for a refusal — while the probe had one
five-second deadline and waited for the second line specifically. So the one machine the check
exists for was the machine it called wedged.

Proof of life is now the first line. A finished `manager=` says the server accepted the `run` and
made the pane, and `probe` cannot be a Needs-you after it. The `fda=` line gets its own ten-second
deadline and, when it never lands, its own fourth answer: `fda` reports that the check did not
finish in time and says what an unfinished check means on macOS. It stays a Needs-you and still
counts against the exit code, because a refusal is what a hung open most likely is — but it is
worded as an unfinished check, not as a denial.

Everything else is untouched: `fda=yes`, `fda=no` and `fda=unknown` print the sentences they
printed, `--dry-run` renders the same lines, and a probe that produces no line at all is still
`TimedOut` in the same words.

The clock and the parser moved to a `session_doctor_probe` module compiled on every platform, so
`probe_step(written, elapsed)` is a pure function with unit tests — answered fast, denied at six
seconds, alive with no answer, nothing at all — instead of behaviour only a Mac can reach.

## Operator notes

- **The doctor's answer changes on a Mac without Full Disk Access.** A machine that read as
  `probe … may be wedged` now reads as `fda=no`, or as `fda … did not finish in time` when the
  refusal outlasts ten seconds. Both are Needs-you and both still exit non-zero; the fix is the
  same grant it always was.
- **A resurrected pane that exits 0 records a shell.** A pane at a prompt serializes the default
  shell as nothing, so the next resurrection brings it back as a plain shell in the same directory
  rather than offering the command again. That is what pressing ESC always cost; it is now paid
  without the keypress.
- **No config change is needed for this release.** Nothing was added to `config.kdl` and nothing
  read from it changed meaning.
