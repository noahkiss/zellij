# v0.45.0-nkmk.12

- **Upstream base:** `f42ca3c79` on upstream `main` (workspace version `0.45.0`) — unchanged since
  nkmk.1
- **Range:** `ee7618967..main` (4 commits)
- **Released:** 2026-08-16

This release is about the shape of a session surviving the ways a machine ends one, and about the
command surface answering less than it knows.

`session up` used to mean two different things. It now comes back with the shape the session had,
and `--fresh` is the way back to the layout. The server serializes and archives on SIGTERM, so a
reboot leaves a snapshot for the `up` that follows it. And a new `pane_privacy` block names panes
the session keeps to itself: their rows are dropped from every listing, and every command naming one
answers as it answers for a pane that was never there.

The release process changed too. A patch is now proved as a release candidate on its own branch
before it lands.

## Added

### `session up` comes back with the shape the session had

```
zellij session up      [NAME] [--fresh | --restore [ID]]
session_up_resume true   # config.kdl, top level, default true
```

`up` ends in `attach --create`, and `attach` resurrects a dead name from the in-place cache by
itself. So a crash, a SIGKILL and a reboot already came back with the previous panes. But
`session down` and `delete-session` **remove** that cache after archiving a snapshot of it, so the
same command after a `down` built the session from the layout instead. Nothing but an explicit
`--restore` ever read the archive.

That gap is not a rare one. The watchdog runs `session up` every minute, so a `session down`
followed by a minute of doing something else came back as a default layout while the shape sat in
the archive.

`up` now resolves one of three sources, in this order:

| What is on disk | What `up` builds from |
|---|---|
| the in-place cache | that (unchanged — `attach` does it) |
| no cache, a snapshot for this name | the **newest snapshot**, named with its age in the output |
| neither | the layout (unchanged) |

`--fresh` is the way to the layout, and it discards the in-place cache rather than ignoring it, the
same as `attach --no-resurrect`. The archived snapshot survives that, so a shape thrown away by
`--fresh` is still reachable with `session up --restore`.

Two behaviours follow from the difference between a shape somebody **named** and a shape `up`
**derived**:

- `--restore` into a running session still exits 2. A bare `up` that finds the session running
  reports "already running" as it always did, and does not start exiting 2 at the watchdog once a
  minute.
- A snapshot that no longer parses fails the command when it was named, and only **warns** when `up`
  picked it. A watchdog tick that leaves the machine with no session at all is a worse answer than a
  session from the layout and a line saying why. The unreadable snapshot is left on disk.

`session_up_resume false` in `config.kdl` restores the old behaviour. It is a top-level key, so a
binary that predates it ignores it rather than failing the whole config.

The cost of the new default is that a `down` followed by an `up` a fortnight later rebuilds a
fortnight-old shape. That is the requested semantic, and it is why the output names the snapshot and
its age rather than restoring quietly.

### `pane_privacy`: panes the session keeps to itself

Some work is nobody's business but the person at the terminal's. A session can be told which panes
those are, and the panes then stop existing as far as the command surface is concerned.

```kdl
pane_privacy {
    patterns_file "/path/to/private-paths.txt"
    pattern "some-extra-regex"
    match_fields "cwd" "command"
    on_unknown_cwd "withhold"
    tab_rule "any"
}
```

Every entry is optional. `patterns_file` names a file of one extended regular expression per line,
`#` comments and blank lines ignored. `pattern` is the same thing written inline, and repeats.
`ZELLIJ_PANE_PRIVACY_FILE` overrides `patterns_file`, because which directories are private is a
fact about a machine and one `config.kdl` is shared across several.

Patterns are matched case-insensitively and are **not anchored**, so an existing list of private
paths is usable as it stands. With no file, no pattern and no environment variable there is no
policy, and the feature costs one `is_active()` per call.

`match_fields` chooses which columns a pattern is tried against — `cwd`, `command`, `title`,
`tab_name`. The default is `cwd command`. `on_unknown_cwd` decides a terminal pane whose cwd is not
known yet, and `withhold` (the default) closes that window. `tab_rule` decides how a tab inherits
its panes' verdict; `any` withholds the whole tab when one pane matches, because a tab name alone
can say what the work is.

**Withholding is not redaction.** A withheld row is dropped, and the only thing left behind is a
count.

What each command does with a policy in force:

| Command | Behaviour |
|---|---|
| `list-panes`, `list-tree` | withheld rows dropped; the table gains a `withheld: n` footer |
| `list-panes --json` | still a bare array — `--report-withheld` switches it to `{"panes": [...], "withheld": n}` |
| `list-agents` | the same; `--report-withheld` gives `{"agents": [...], "withheld": n}` |
| `list-tabs` | withheld tabs dropped |
| every `--pane-id` verb (`dump-screen`, `wait`, `send-keys`, `close-pane`, …) | `No pane answers to '<target>'`, exit 2 — the unknown-pane answer |
| a verb naming a withheld tab | that verb's own no-such-tab answer |
| `new-pane --cwd`, `new-tab --cwd`, `run --cwd` under a matching directory | the directory is dropped, as it is for a directory that does not exist |
| `dump-layout`, `snapshot show`, `snapshot restore` | refused whole while any policy is active |
| `snapshot list`, `ls` | unchanged |

**A refusal is the ordinary miss, byte for byte.** A message that said "withheld" would be a yes/no
oracle on any string the caller cared to pass, and because patterns are unanchored substrings, a
loop over that oracle recovers the pattern list itself. So a withheld pane answers `No pane answers
to '<target>'` at exit 2, a withheld tab gets that verb's own no-such-tab answer, and a withheld
`--cwd` is dropped from the request — which is what zellij already does with a directory it cannot
use, pane made, no error, `list-panes` reporting the server's cwd.

The aggregate `withheld: n` count on `--report-withheld` and in the MCP's `zellij_overview` is the
only output that admits a policy is running. That is deliberate: a caller should know its view is
partial. It is a count and never a name. `dump-layout`, `snapshot show` and `snapshot restore` keep
a plain refusal, because a whole document has no per-target answer to imitate and so no oracle to
build.

**The server decides, in `route.rs`.** That is where every CLI verb arrives, and every `zellij mcp`
tool runs this binary's CLI in a child process. So one filter covers an agent holding the MCP tools
and an agent holding a shell, without being written twice. There is no flag to turn it off for one
call.

A `patterns_file` that cannot be read, or a pattern that does not compile, makes the policy
**broken**: every pane is withheld and every targeted call answers as a miss, with the reason in the
session log. A privacy filter that fails open is a filter that silently is not there.

One pre-existing wrong answer went with it. `wait <id> --for exit` on a pane that never existed
used to return `waited_ms: 0` and exit 0, because an id form resolved to itself without anyone
asking whether a pane held it. An unknown id is now a miss like an unknown handle, which is also
what makes a withheld pane answer the same way.

Three things it does not cover. A plugin subscribed to `Event::PaneUpdate` still receives every pane
— the plugin event path does not go through the CLI route handlers. `go-to-tab-name` reaches a
withheld tab by its name, which a caller has to guess. And anyone looking at the terminal sees the
panes; this is about what the command surface answers, not about what is on screen.

The block is top level, so a binary that predates it ignores it and the config can go out ahead of
the upgrade. Its own children are strict, so it cannot be rolled out one key at a time.

## Fixed

### No caller may replace an anchored pin signature without signing (macOS)

nkmk.11 made doctor refresh and sign the pinned copy as one transaction, so a locked keychain left
the previous signed pin in place instead of replacing it with an ad-hoc copy and voiding every macOS
grant. It named the remaining gap and did not close it: **`session up` still did the plain copy**,
with no signing step in it.

That gap was the one that mattered. The watchdog runs `session up` every minute, so on an upgraded
machine `up` reaches the pin first and a `session doctor` typed afterwards is too late — the grants
are already gone. Proving nkmk.12 on a Mac stopped short of `session restart` for exactly this
reason: the restart would have destroyed the pin's signature.

The rule was written into `session up`'s own path first, and that was not enough. **The pin had two
writers.** An interactive launch resolves the server binary through the pin as well, and that path
called the copy directly — so on a Mac the refusal printed and the signature was destroyed a moment
later, in the same command, by the caller nobody had told.

The rule now lives at the write. There is ONE writer of the pin, and it refuses to overwrite an
existing pin that carries an anchored signature: it either refreshes it through the signing
transaction, or leaves it exactly as it was. `session up`, `session restart`, `session enable`,
`session doctor --fix` and every interactive launch get that behaviour without asking for it,
because there is no longer a way to ask for anything else.

If every signing rung refuses — a locked keychain, which is every unattended launchd run —
**nothing is written**: the session comes up on the previous build, with its signature and its
grants intact, and says so once in the signing step's own words, pointing at
`zellij session doctor --fix` from a desktop terminal. A pin that is current, already ad-hoc, or
unsigned still takes the plain copy. `session doctor --no-sign` now leaves an anchored pin both
unsigned and unreplaced, where it used to copy over the signature. Linux is unchanged.

### The server serializes and archives on SIGTERM

A session used to die badly on the ordinary ways a machine ends one. `systemctl --user stop`, a
logout and a reboot all send the server SIGTERM, and the server had no handler for it. The process
went at once, so the newest shape on disk was whatever the periodic serializer last wrote — up to a
whole `serialization_interval` old, 60 seconds by default — and **no snapshot was archived at all**.
The one moment a person most wants the shape back is the reboot, and it was the one path that cut
nothing.

The server now listens for SIGTERM on its own thread and sends itself `KillSession`, which is the
graceful path `zellij kill-session` has always taken: serialize once more, tell every client, then
archive on the way out. Nothing new can hang in it that could not hang there.

The thread is not started for the in-process server the integration tests run. That one shares the
harness's process, and a test runner's signals are not its to answer.

It pairs with `session up` resuming by default: the reboot now leaves a current snapshot, and the
`up` that follows it finds one.

## Changed

### A patch is proved as a release candidate before it lands

A patch is now developed on its own branch and proved with an RC tag pushed from that branch —
`v0.45.0-nkmk.12-rc.1` — before it is squash-merged and the final tag is cut from main.

An RC builds and publishes exactly like a final tag, with two differences: the GitHub release is
marked as a prerelease, and the tap bump rewrites a separate `zellij-nkmk-rc` formula. So a Mac can
install a candidate without disturbing the formula every machine runs:

```
brew update && brew unlink zellij-nkmk
brew install noahkiss/tap/zellij-nkmk-rc
# ... prove the patch ...
brew uninstall zellij-nkmk-rc && brew link zellij-nkmk
```

The version the binary reports carries no `-rc.N`. The branch bumps `Cargo.toml` to the final
version, so `zellij --version` prints `0.45.0-nkmk.12` under a `v0.45.0-nkmk.12-rc.1` tag, and the
tap strips the suffix before comparing.

`finalize` sets the prerelease flag in both directions, so rebuilding an existing tag does not
inherit whatever it was marked as last time.

AGENTS.md also stopped claiming CI runs on Windows. `rust.yml` is ubuntu and macOS only, and Windows
is not a shipped target.

## Upgrading

Nothing is required. Two new config keys are available and both are top level, so a binary that
predates them ignores them:

- `session_up_resume false` opts out of `session up` resuming the last shape.
- `pane_privacy { ... }` turns on the privacy filter. With no block there is no policy and nothing
  changes.
