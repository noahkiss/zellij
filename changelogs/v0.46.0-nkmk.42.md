# v0.46.0-nkmk.42

- **Upstream base:** unchanged — the `v0.46.0` release tag (`aedee21cb`)
- **Range:** `v0.46.0-nkmk.41..v0.46.0-nkmk.42`
- **Released:** RELEASE-DATE

This release makes agent messages say where they come from, and lets panes on macOS ask for the microphone.
It also makes the macOS status-bar probe cheap and stops a new shell's startup from swallowing the first typed command.
A running session needs a restart to use this release.

## Added

- **A message can come from the person.** `send-message --from-person` and the MCP `zellij_send` `from_person` mark a message as the person's own words or request, relayed by an agent. The envelope then says it comes directly from the person, through another session. The name is the new `person_name` config option; without it the envelope says `user`.
- **Claude Code receives a message as a cross-session message.** A message to a Claude Code agent comes inside `<cross-session-message>`, with the envelope as attributes: sender, tab, message id, how to reply and, when set, `origin`. Claude Code draws a one-line message as one collapsed "Message from" line; a longer one shows the wrapper, and the agent reads it the same. Other harnesses keep the envelope line above the text.
- **Panes can ask for the microphone (macOS).** The binary embeds an Info.plist with `NSMicrophoneUsageDescription`, and the release is signed with the `audio-input` entitlement. The first program that asks gets the system prompt; every pane inherits the answer.

## Changed

- **The macOS vitals probe samples CPU with `iostat`, not `top -l 2`.** `top` walked every process twice, at about 0.4 s of CPU a probe. `iostat -c 2 -w 1` takes the same one-second sample at no measurable CPU.
- **A failed vitals probe keeps the other bars deferring.** A probe that fails or is killed still tells the other bars of its session, so they do not all probe in the same tick.
- **`--wait-ready` waits 1.5 s of quiet before a new shell counts as ready**, up from 300 ms. A shell that printed a line and then paused to load plugins read as ready too early, and the command typed next landed in its startup. A shell that writes OSC 133 marks is still ready at its first prompt. `wait --for ready` keeps 300 ms.

## Fixed

- **`zellij_send` no longer reports a queued message as an error.** The tool's output schema now accepts the reason a held message carries (`working`, `typing`, ...).

## Compatibility

- **Restart needed: yes.** The server changed: the vitals plugin and the message envelope live in it.
- **`--from-person` against an older server.** The flag travels as a new field of the message action. An nkmk.41 server ignores it and sends the plain envelope.
- **Config:** `person_name` is a new top-level option. An older binary ignores an unknown top-level key.
- **Exit codes and JSON keys:** unchanged, except `message-status` records may carry `from_person`.
