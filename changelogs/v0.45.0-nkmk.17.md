# v0.45.0-nkmk.17

- **Upstream base:** the `v0.45.0` release tag (`13e1c25a2`) — moved from `98a083707`, which was
  twelve commits shy of it
- **Range:** `v0.45.0-nkmk.16..main`
- **Released:** 2026-08-21

The release where the fork gets honest about what it is. The base is a released upstream tag again
instead of a main-branch commit, and the binary now says so: `--version` prints the upstream base
it was cut from, a release candidate reports its own `-rc.N` instead of impersonating the final,
and the bundled plugin assets no longer name the machine that built them. Around that: the watchdog
tightens from a minute to fifteen seconds, launch agents can carry arbitrary environment variables
from config, and the tab bar stops treating a trackpad flick as a request to tour every tab.

## Changed

### The base is the `v0.45.0` release tag

The series was rebased from upstream-main commit `98a083707` onto the `v0.45.0` tag proper — a
twelve-commit hop of fixes and release notes; every headline 0.45 feature was already beneath the
fork. Two patches dropped out as upstream-absorbed (the tab-position sort, the IPC receive-error
split), one proto tag moved into the fork-reserved block (`move_tab_to_index`, 148 → 172, no
contract change), and the Full Disk Access page patch got smaller by adopting upstream's
substring-based help coloring. The v16-era commits were also condensed to one commit per ledger
entry.

### The watchdog ticks every fifteen seconds

`CHECK_INTERVAL_SECS` drops from 60 to 15 on both platforms at once. Measured first: a pass over a
healthy session costs 0.16–0.17 s, about one percent of the new interval.
`watchdog_interval_secs` still overrides in either direction.

### The tab bar ignores the wheel

`slim-tab-bar` no longer switches tabs on scroll. Switching is deliberate only — a click or a
keybind. The stock bars keep their upstream behavior.

## Added

### `--version` names the upstream base

A second line: `upstream v0.45.0 @ 13e1c25a2`, plus `built YYYY-MM-DD` on release artifacts. The
first line is byte-identical to before, so everything that parses it is untouched. `setup --check`
gains an `[Upstream base]` line.

### An rc binary reports the rc

A candidate tag now bakes its full version into the build: `v0.45.0-nkmk.17-rc.1` produces a
binary that prints `0.45.0-nkmk.17-rc.1`. The tap's install check and the rc formula assert the
whole version, suffix and all — a Mac can no longer be running a candidate that calls itself the
release.

### The launchd `env` block

`session_service { launchd { env { NAME "value" } } }` lands in the generated plist's
`EnvironmentVariables`, each entry written exactly once, generator defaults still applied unless
overridden.

## Fixed

### The checked-in plugin assets stop naming the machine that built them

All fifteen `.wasm` assets embedded the absolute home directory of whoever last rebuilt them. The
plugin build now remaps `$HOME`, `$CARGO_HOME`, and the project root; rebuilds are byte-identical
wherever they run.

## Operator notes

- **The watchdog change shows as drift.** A machine that installed its units under the old 60 s
  default reports the timer/plist as stale in `session status` until `session enable` is re-run
  there. That is the drift check working; re-enable at the next convenient moment.
- **`launchd { env { … } }` is a nested key.** A binary older than nkmk.17 fails the whole config
  on it. Upgrade every machine before the key appears in shared config.
- **The tap change is already live.** `bump-zellij.yml` and the rc formula now expect full rc
  versions; older rc tags can no longer be re-driven through the bump workflow (they were never
  install targets).
