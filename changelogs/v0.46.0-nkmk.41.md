# v0.46.0-nkmk.41

- **Upstream base:** moved — the `v0.46.0` release tag (`aedee21cb`), from `v0.45.1`
- **Range:** `v0.45.1-nkmk.40..v0.46.0-nkmk.41`
- **Released:** 2026-11-20

This release moves the fork onto upstream 0.46.0.
The fork drops the patches nothing used, and moves its protocol tags into a reserved block.
Agents can now message each other: `send-message` types a message in only when the receiving agent is idle and nobody is typing.
A running session needs a restart to use this release.

## Upstream base

Upstream 0.46.0 is a large release. A user notices the right-click menu, popups and notifications, and an interactive configuration screen. Tabs reorder with the mouse, stacks can be horizontal, and the tab bar and status bar can be hidden at runtime. Upstream now parses OSC 7501 itself and keeps an inbox of cross-session activity. Output and scrolling are faster, and the server uses less memory. Upstream also adds a desktop terminal window. The full list is in `CHANGELOG.md`.

## Removed

The fork removed the patches no caller used, so each rebase carries less. [docs/removed-patches.md](../docs/removed-patches.md) lists each one, the last release that had it, and where its code still lives. The larger ones:

- `pane_privacy`, `report_pane_env`, `managed_session`, `watchdog_interval_secs` and `builtin_plugin_dir` (config keys no machine set);
- the image viewer (`action show`, `zellij_show`), `drop-file`, `signal-pane`, `set-pane-note`, `list-events`, `reload-template`, the `break-pane` verbs and the idempotent `set-*` verbs;
- `list-agents --watch`, `subscribe --all` and `snapshot import`;
- the MCP tools `zellij_arrange` and `zellij_snapshot`, and `zellij_create` `run_in=agent` and `run_in=plugin`;
- the session manager's archive picker and client list, and the plugin lifecycle events;
- nine `PaneInfo` fields (the eight pane state fields and `focused_by_client_ids`);
- choosing a pane's handle at creation (`--handle`).

`new-pane --stacked` with nobody attached and no target is now refused by upstream's own check, with exit 1.

## Changed

- **Protocol tags.** Every fork field and value inside an upstream message now sits in a reserved block from 900, in both the client/server contract and the plugin API. FORK.md "Fork protocol tags live in a reserved block" has the table.
- **`move-tab --to-index`** maps onto upstream's own `MoveTabToPosition`. The fork action for it is gone.
- **Sessions are found by id.** Upstream names a new session's socket by a random id. Every fork path resolves the id first, so fork and stock builds of one contract still share sessions.
- **OSC 7501** is read with upstream's parser. The fork keeps its per-pane records and the flat `state*` keys.
- **`command_state` stays a string.** Upstream's own struct appears on JSON rows as `command_state_detail`. Upstream's other new row keys (`attention`, `program_status`, `nested_session_name`, `is_collapsed`) are added beside the fork's.
- **The tab-mode close key** (`x`) is now `CloseTabOrConfirm` in both presets. A tab with more than one pane asks first.
- **An agent's new pane or tab leaves the person's focus alone.** From a shell with `AGENT_SESSION_ID` set, `new-pane`, `new-tab` and `zellij plugin` make it in the background; `--focus` takes the focus. A person's own command is unchanged.
- **A background plugin hears the session with nobody attached.** A plugin loaded without a pane gets `PaneUpdate` and `TabUpdate` in a detached session too.

## Added

- **`action watch` carries attention.** `pane_changed` carries upstream's `attention` object. A shell with no OSC 133 markers gets `command_state` from upstream's process tracker: `running`, then `done`.
- **Agent messages.** `zellij action send-message --to <agent> -- <text>` and the MCP tool `zellij_send` hand a message to an agent's pane. The session types it in only when the agent reported `idle`, `done` or `error`, nothing typed is waiting in its prompt, and no key came in the last 5 seconds; otherwise it holds the message and tries again each second until it expires. `action message-status` shows held and settled messages.
- **A readable envelope.** Each message names the sender's agent, tab and machine, and offers `reply_to=<id>` and `to=host/session/handle`. Ids are short numbers counted per session. `--reply-to <id>` resolves the id only in the replying pane's own session. The sender does not wait for the answer; it arrives as a message.
- **Agent listings say how to reach an agent.** `list-agents --json` rows carry how to message the agent. The MCP groups agents by host, tab and pane, its `zellij_write_input` hint names the address that reaches the agent, `remote_hosts` takes a short alias for a host, and `zellij_create kind=tab` names the tab.
- **Any harness can be messaged.** A new agent of any harness has a minute to report its state; until then a message waits as `starting`. One that never reports is refused as `no_state`, naming `zellij setup --agent-hooks`. An agent that has reported once is never refused that way.
- **An agent that reported before the session first saw it counts as one that reported.** A message to it after its state was cleared is held as `starting`, never refused as `no_state`.
- **`send-message` starts `default_harness`.** With `default_harness "<name>"` in the config, a message to a tab or pane with no agent starts that harness there, and the message becomes its first prompt.
- **`session restart --when-idle`** waits for the session's agents to go idle instead of refusing. Before tearing down, restart runs the serving build's `--version` and `setup --check`, and refuses a build that fails them. `session status` and `restart --dry-run` say whether a restart is needed.
- **The vitals probe** never overlaps itself, kills itself after eight seconds, and only one bar per session probes.
- **`session doctor` on macOS checks every privacy grant the server needs.** It asks the server for Accessibility and Screen Recording, and names App Management with its Settings link. `--fix` from a terminal asks for one missing grant at a time and opens its System Settings pane.
- **A saved layout with `expanded` outside a stack loads**, with a warning. `session up` names a saved layout that does not parse.
- **`new-pane` and `new-tab` refuse a `--cwd` that names no directory**, and create nothing.
- **An action sent while a session is still starting waits for it.** `zellij -s S action new-tab` right after `attach --create-background S` used to make nothing and exit 0 with no output.
- **Smaller fixes.** A pane made without focus in a full tab leaves the focus alone. A pane stacked in the background leaves the focused pane expanded. A resumed session's new tabs open in the directory they are asked for. A scratch environment (`ZELLIJ_SOCKET_DIR` set, `XDG_DATA_HOME` not) cannot rewrite the real pinned binary.
- **CI fails a change that adds a home path, a private or tailnet address, or a tailnet name**, in its lines or its commit messages.

## Compatibility

- **Restart needed: yes.** This release changes the server. `session status` says so.
- **Fork actions do not cross the tag move.** A fork client from before this release cannot use fork actions or `action watch` against a server from this release or later, and the reverse. A plugin built before this release reads none of the fork's `PaneInfo` fields; the checked-in plugins are rebuilt.
- **Exit codes:**
  - `session restart` exits 2 when the serving build fails its pre-flight.
  - `new-pane` and `new-tab` with a `--cwd` that names no directory exit 2. They used to exit 0 and open the pane in the session's own directory.
- **Focus:** an agent's `new-pane` and `new-tab` no longer move the person's focus. Pass `--focus` for the old behaviour.
- **JSON keys** are only added. A test checks every `list-tree`, `watch` and `ls` key from nkmk.40 against this build.
